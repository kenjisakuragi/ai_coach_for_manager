# 桜木健二 文体ルール｜王道ビジネス解説スタイル × AI書き感の排除

このドキュメントは、桜木健二（AI駆動経営ラボ主宰）がnote記事を書くための実務ルールです。

目指すのは **「情報網羅性 × 構造の明快さ × 王道ビジネス解説」** 。エッセイ的な物語型ではなく、読者が「学びになった、保存しておきたい」と思える解説記事を量産する。

参照する書き手の方向性：
- 北野唯我（『天才を殺す凡人』）：論点を構造化、フレームワークで束ねる
- 山口周（『ニュータイプの時代』）：教養と論理で説得、引用を効果的に使う
- 馬田隆明（『未来を実装する』）：図表・分類で網羅、定義から入る
- 入山章栄（早稲田大学）：理論×事例×示唆の3点セット
- 安宅和人（『シン・ニホン』）：問いを立て、データで答える
- 田端信太郎：論点を強く打ち出し、骨太に解説

本ルールは、これら「王道型ビジネス解説」の構造を借りつつ、AI書き感を消すための実務ガイドです。

## 第1章：AI書きの典型的シグナル（やってはいけないこと）

桜木既存記事 `02_akiyoshi_ai.md`（旧版）の分析と、生成AIが書きがちな文章の特徴から、以下を **絶対NG** と定める。

### 1-1. 構造のNGパターン

- **「検証済み引用①〜⑥」のような機械的番号付け見出し**：人間は見出しに「①検証済み」と書かない
- **「｜（縦棒）」を使った二段見出しを連発**（1記事3回以上）：テンプレ感が強い
- **「はじめに｜なぜ◯◯から学ぶのか」型の見出し**：AI生成テンプレの典型
- **すべての段落が「結論→根拠→翻訳」の3段で均一**：人間の文章にはブレがある
- **架空ペルソナ（Aさん／Bさん／Cさん）を3人並べる**：1人なら可、複数並べるとフィクション臭くなる
- **「⚠️ 以下は架空のシナリオです」のような注記**：リスク回避ロジックが文章に染み出している
- **「桜木さんへ｜公開時の確認事項」「TODO」「[ ]」が本文末に残る**：作業メモ流出の最大シグナル

### 1-2. 文末・語彙のNGパターン

これらの語が出たら、書いた直後に消す：

- 「すべてを物語っています」
- 「衝撃的な数字です」
- 「これは……への重要な問いかけです」
- 「設計思想そのもの」
- 「本質」「核心」「象徴」を **同一記事に複数回**（1回までなら可）
- 「フルコミット」を引用以外で使う
- ロングダッシュ「——」を1記事に5回以上

### 1-3. 装飾のNGパターン

- **絵文字（🎓📦✉️✅⚠️）を本文・見出しに入れる**：UI絵文字は読み物のノイズ
- **太字を1段落に2回以上連続**：強調が強調にならない
- **矢印＋未来予言太字**「→ **3か月後、あなたは◯◯になっています**」：LLMが結論を強調する典型ムーブ
- **数値・固有名詞を太字にする**：読み手は数字を勝手に拾うので不要

## 第2章：王道ビジネス解説スタイルの構造

### 2-1. 記事の典型構造（推奨フレーム）

王道ビジネス解説記事は、おおむね次の7ブロック構造で成立する：

1. **タイトル**（記事の価値を明示）
2. **導入**（誰のための記事か、何が学べるか、200〜400字）
3. **背景・前提情報**（読者の認識を揃える）
4. **論点の構造化**（3〜5論点を見出しで区切る）
5. **各論点の解説**（引用・データ・フレームワーク・具体例）
6. **まとめ**（論点を再整理、実装指針に落とす）
7. **出典・著者情報**（信頼性を担保）

各論点の解説（5）の中身は、**「定義→根拠→事例→示唆」** の4ステップで構成する。

### 2-2. タイトルの型

王道ビジネス記事のタイトルは、以下のいずれかの型を取ることが多い：

- **「◯◯の全体像｜〜が学ぶべき◯個のポイント」**
- **「◯◯氏が語った◯◯戦略を、◯◯向けに解説する」**
- **「【保存版】◯◯を理解するための◯個のフレームワーク」**
- **「なぜ◯◯なのか？〜の構造を解き明かす」**

「3個」「4個」「5個」など **奇数** が好まれる傾向がある（偶数は「4つの〜」のように4でも問題ない）。

### 2-3. 導入文の型

導入は、以下の3要素を200〜400字に収める：

1. **誰の発言／どの事象を扱うか**（事実の提示）
2. **なぜそれが重要か**（読者にとっての意味）
3. **本記事で何を解説するか**（ロードマップ）

### 2-4. 見出しの型

見出しは **「論点◯：◯◯◯◯」** の形式が、最も網羅性と構造性を両立する。

OK例：
- 「論点1：AXトランスフォーメーションへの『フルコミット』」
- 「論点2：『ラストワンマイル人間化』という業務設計思想」
- 「論点3：経営者を含めた個のエンパワーメント」

NG例（旧版で使っていた型）：
- 「## 検証済み引用①｜AX（AIトランスフォーメーション）コミット」（機械的番号）
- 「## はじめに｜なぜ秋好CEOから学ぶのか」（テンプレ感）

### 2-5. 引用の扱い

引用は、ビジネス解説記事の **信頼性の源泉** であり、王道スタイルでは積極的に使う。

- **直接引用は記事内に5〜10箇所**を目安に配置
- 引用ブロック（`> 〜`）で明確に区切る
- 出典を引用直後 or 記事末尾でまとめて明記
- 短い引用（30字以下）は本文中に「〜」で組み込む
- 長い引用（30字超）は引用ブロックで独立表示

引用の出典書式：

```
> 「引用文」
> （出典：媒体名、日付、発言者）
```

### 2-6. 太字の使い方（王道スタイル）

王道ビジネス解説では、太字は **「読者が拾ってほしいキーワード」** に積極的に使う。1記事10箇所縛りは不要。

太字を使うべき場面：
- **概念の名付け**（例：「**ラストワンマイル人間化**」）
- **結論文の強調**（例：「**経営者がAIを号令だけで終わらせず、自ら使う側に立つ**」）
- **重要な数値の強調**（例：「**月40時間が16時間に減る**」）
- **対比の片側を強調**（例：「単一業務ではなく、**複合的な掛け算で達成される**」）

太字の禁止事項：
- 1段落に2回以上連続させない
- 矢印＋未来予言太字「→ **〇〇になっています**」をやらない
- 引用ブロック内では太字を使わない（引用は引用として尊重）

### 2-7. 箇条書き・テーブル

王道ビジネス解説では、**情報の構造化** のために箇条書き・テーブルを積極利用する。

#### 箇条書きを使うべき場面
- 並列の情報を3〜7個列挙する時
- ステップ・段階を順序立てて示す時
- 対比する2グループを示す時

#### 箇条書きの注意点
- 8項目以上は読者が把握しきれない（分割するかテーブル化）
- 1項目1〜2行に収める（長文を箇条書きで書くと読みにくい）
- 入れ子（ネスト）は2階層まで

#### テーブルを使うべき場面
- 2〜4列の比較が必要な時
- フレームワークを2軸で整理する時
- ステップごとの状態変化を見せる時

#### テーブルの注意点
- 3列までは読みやすい、5列を超えると読み手の負荷が高い
- すべてを表にしようとしない（「Before/After」だけのために表を作るのは過剰）
- スマホでの可読性を考えて、列幅を意識する

### 2-8. フレームワーク・分類

王道スタイルの核は、**情報を網羅的にカバーしつつ、フレームワークで構造化する** こと。

頻出するフレーム：
- **3層構造**（戦略／戦術／実装、など）
- **2軸マトリクス**（重要度×緊急度、など）
- **段階モデル**（Phase 1〜4、など）
- **対比構造**（従来 vs 新しい、など）
- **チェックリスト**（◯◯を確認する10項目、など）

桜木の記事では、最低 **1記事に1フレーム** を入れることを推奨する。

### 2-9. 筆者の見解

王道ビジネス解説では、筆者の見解は **論点ごとに1〜2行で挿入** する。

- 「私は、これを **〇〇** と呼んでいる」
- 「実務で見る限り、これは ◯◯ にほぼ該当する」
- 「私の経験では、ここで失敗するケースが多い」

エッセイ型のように **段落全体を自分語り** にしない。情報の合間に、見解を一筆入れる程度に抑える。

### 2-10. 具体例・エピソード

具体例は、論点の **理解を助けるための補強** として配置する。

- 1論点につき具体例は1個まで
- エピソードは2〜3行で済ませる
- クライアント名は「神奈川の和食店オーナーSさん」のように業種＋頭文字で抽象化
- 数字を出す場合は「年商3,500万→5,500万」のような細かい数値ではなく、「2倍」「3か月で月30時間削減」のような実感ベースに

エピソードを長く書きたい場合は、**別途エッセイ記事として独立させる**。解説記事と混ぜない。

### 2-11. まとめの型

王道スタイルの結論部は、**論点を再整理して実装指針に落とす** のが定型。

```
## まとめ：◯◯から抽出した◯個の実装指針

本記事で取り上げた論点を、〇〇が明日から実装できる形に整理する。

1. **論点1の指針**
2. **論点2の指針**
3. **論点3の指針**
4. **論点4の指針**

[1〜2文の総括メッセージ]
[著者の体感・経験を1〜2文添える]
[最初の一歩の提案]
```

エッセイ型の「比喩で抜ける」「自嘲で抜ける」結びは、解説記事には合わない。

## 第3章：桜木健二の文体ルール（実務ガイド）

### 3-1. 1文・1段落の長さ

- **1文は40〜80字を中心**、結論文や強調文は短く（20〜40字）
- **1段落は3〜5文**で改行
- 連続する長段落（5文超）を避ける
- 1段落で1論点に絞る

### 3-2. 文末リズム

- 基本は「です・ます」調
- **論点の結論文や定義文は「だ・である」** で引き締めると良い
  - 例：「これは、AI導入における二択を否定する設計思想だ」
- 「〜なのです」「〜と言えるでしょう」「〜のではないでしょうか」を1記事3回以下に抑える
- 体言止めは1記事3回まで（広告感が出る）

### 3-3. 数字・データの扱い

- 数字は文章に **積極的に組み込む**
- 「**月40時間が16時間に減る**」のように、Before/Afterを並べる
- パーセント・倍率は **読み手がイメージできる単位** に翻訳
  - NG：「生産性が500%向上」
  - OK：「生産性が5倍、つまり1人で5人分の仕事が回る」

### 3-4. 専門用語の扱い

桜木の口癖「難しいことをやさしく、やさしいことをふかく」を文体に反映する：

- **専門用語を出した直後にカッコで言い換える**
  - 例：「AX（AIトランスフォーメーション、AIを前提とした業務再設計）」
- **横文字には日本語訳を併記**
  - 例：「ラストワンマイル人間化（最終出口だけは人間が担う設計）」
- **抽象論の後に1行の具体例**
  - 例：「概念としてはこうだ。実例で言うと、議事録は AI、誕生日のお品書きは経営者本人、というような切り分けである」

### 3-5. 「私（桜木）」の出し方

- 自分の見解は **論点解説の終盤に1〜2行** で挿入する
  - 例：「私の実務感覚では、ここで多くの経営者がつまずく」
- 自分のクライアント事例は **1記事1人まで**（複数並べると架空ペルソナ感が出る）
- 自分の経歴（東大近山研／元塾講師）は **1記事に1回まで**
  - 出すなら、著者紹介ブロックか、1論点の補強として1回

### 3-6. 読者への呼びかけ

- 「あなた」を多用しない（説教調になる）
- 「経営者の方は」「スモールビジネスオーナーは」「読者は」のように **集団主語** にする
- 「みなさん」は使わない（読者層が広く感じられる場合のみ可）

## 第4章：記事のひな形（王道スタイル）

### 4-1. タイトル

```
◯◯氏が語った「◯◯◯◯」の全体像｜
〜が学ぶべき◯個の論点
```

または

```
【保存版】◯◯を理解するための◯個のフレームワーク
```

### 4-2. 導入（200〜400字）

```
[誰が／何が起きたか]（2〜3文）
[なぜそれが重要か]（2〜3文）
[本記事で何を解説するか]（1〜2文）
[出典の信頼性についての一言]（1文）
```

### 4-3. 各論点ブロック（500〜1000字 × 3〜5論点）

```
## 論点◯：[論点を端的に表す名詞句]

[論点の定義・前提を1段落（2〜4文）]

> 「直接引用」
> （出典：◯◯）

[引用の解説1段落（2〜4文）]

### [小見出し：その論点をさらに細分化]

[フレームワーク・分類・段階の提示]

- [箇条書きまたは表]

[筆者の見解・実務感覚を1〜2行]
```

### 4-4. まとめブロック

```
## まとめ：◯◯から抽出した◯個の実装指針

[本記事で扱った論点を要約する1段落]

1. **論点1の指針**
2. **論点2の指針**
3. **論点3の指針**
4. **論点4の指針**

[総括メッセージ1〜2文]
[筆者の体感・実例1〜2文]
[最初の一歩の提案1〜2文]
```

### 4-5. 出典・著者紹介ブロック

```
---

## 出典

1. **媒体名**（日付）
   URL

2. **媒体名**（日付）
   URL

---

**桜木 健二**
AI駆動経営ラボ 主宰
```

8. [ ] 引用の出典が明記されているか
9. [ ] 数字・データが文章に組み込まれているか

### 構造化要素チェック

### 文体チェック
13. [ ] 「だ・である」と「です・ます」が論点の結論で適切に使い分けられているか
14. [ ] 専門用語の直後に言い換えが入っているか
15. [ ] 筆者の見解が論点ごとに1〜2行に抑えられているか

### AI書きシグナル排除チェック
18. [ ] 「①〜⑥」「検証済み引用①」のような機械的番号付け見出しがゼロか

20. [ ] 「桜木さんへ」「TODO」「[ ]」のような作業メモが本文に残っていないか

このチェックリストを **記事末尾の運用メモには絶対残さない**（本文と別ファイルで管理）。

## 第6章：王道ビジネス解説 トーンサンプル

### サンプル1（導入）

> ランサーズ株式会社の代表取締役社長CEO・秋好陽介氏は、2025年5月の決算説明会で、AI活用について明確な方針を示した。
>
> その内容は、上場企業の決算文書としては異例なほど、AIに対する個人的なコミットメントと具体的な数値目標が織り込まれていた。
>
> 本記事では、秋好CEOの公開発言から4つの論点を整理し、スモールビジネスオーナーが自社で実装する際の具体的な指針に翻訳する。引用はすべて、ランサーズ社の公開IR資料および本人インタビュー記事からのものだ。

### サンプル2（論点解説の冒頭）

> ## 論点2：「ラストワンマイル人間化」という業務設計思想
>
> 秋好CEOは、AI導入の設計思想について次のように述べている。
>
> > 「AIでできるところはAIでいいよ、もしくはAIでできない人間しかできないところのラストワンマイルを人間でやってほしい」
>
> これは、AI導入における **「全部任せるか／全部やるか」の二択を否定** する設計思想だ。

### サンプル3（フレームワーク提示）

> ### 業務切り分けの基本原則
>
> スモールビジネスにこの思想を当てはめると、業務はおおよそ次の2種類に分類できる。
>
> **AIに任せる業務（プロセスの大部分）**
> - 議事録の文字起こし・要約
> - メール下書き・情報整理
> - リサーチ・データ集計
> - SNS投稿の下書き
>
> **人間が担う「ラストワンマイル」**
> - 重要顧客への最終返信
> - 値段交渉・契約締結
> - 採用面接の判断
> - 新規事業の意思決定
>
> 私の実務感覚では、この線引きを明文化するだけで、経営者の3か月後の業務時間が大きく変わる。

### サンプル4（まとめ）

> ## まとめ：秋好CEOから抽出した4つの実装指針
>

## 第7章：エッセイ型との使い分け

本ルールは「王道ビジネス解説」を主軸とするが、書き手としてのキャラ確立のため、**エッセイ型を年に2〜4本** 混ぜることを推奨する。

| スタイル | 用途 | 頻度 |
|---|---|---|
| **王道ビジネス解説**（本ルール） | ◯◯氏の発言解説、フレームワーク紹介、Howto系 | 月3〜5本 |
| **エッセイ型** | 自分の体験・気付き、業界批評、独白系 | 月0〜1本 |

エッセイ型を書く時は、別ルール文書（`writing_style_essay.md` などで分離管理）に基づく。本ルールはあくまで **解説記事用** である。
