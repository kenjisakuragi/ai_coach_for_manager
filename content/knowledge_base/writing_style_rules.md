# 桜木健二 文体ルール｜「Claude Code経営活用事例」シリーズの執筆指針

このドキュメントは、桜木健二（AI駆動経営ラボ主宰）が note で展開する **「Claude Code経営活用事例」シリーズ** を中心に、note記事を書くための実務ルールです。

目指す文体は **「林修・池上彰スタイルの解説記事、ただし中小企業経営層に刺さる業務寄り」** 。難解な概念を身近な例えで噛み砕き、読者の知的好奇心を刺激しながら、最後には実装可能な指針と、桜木のバックエンド商品「経営者向けAIの家庭教師」への自然な導線につなげる。

---

## 第0章：シリーズの全体設計

### 0-1. シリーズの目的

note 記事は、それ自体で完結する読み物ではなく、以下のファネルの中で機能する：

```
[Claude Code経営活用事例シリーズ（note記事群）]
    ↓ 専門家として信頼を蓄積
[読者が「この人の話を直接聞きたい」と思う]
    ↓
[無料相談（Calendly 30分）]
    ↓
[経営者向けAIの家庭教師（バックエンド商品）]
```

つまり、各記事は「役立つ事例解説」であると同時に、**桜木が経営者向けのAI伴走者として信頼に値する** ことを示す材料でもある。

### 0-2. シリーズ記事のタイトル形式

```
Claude Code経営活用事例｜[経営者名][肩書][の場合]
```

例：
- 「Claude Code経営活用事例｜ランサーズ秋好社長の場合」
- 「Claude Code経営活用事例｜DeNA南場会長の場合」
- 「Claude Code経営活用事例｜キープレイヤーズ高野さんの場合」

### 0-3. 「事例」の意味と帰属の正確性

「Claude Code経営活用事例」というタイトルは、**桜木の分析的な事例研究** という意味で使う。取り上げる経営者本人が必ずしも「Claude Code」を使っていると主張しない。

帰属の原則：
- 経営者本人の発言は **公開資料からの直接引用** に限定する
- 「Claude Code を経営に取り入れる視点で読み解く」というのは桜木の分析の枠組み
- 経営者が AI 全般について語った発言を、Claude Code 視点で再解釈する形を取る
- 「[経営者名]さんは Claude Code を使っている」とは絶対に書かない（事実確認できないため）

### 0-4. 各記事の終盤での導線

各記事の末尾には、必ず以下のブロックを **本文の自然な流れの一部** として配置する：

```
## 桜木からのお知らせ：「経営者向けAIの家庭教師」

[読者が記事を読んで抱きそうな本音を、桜木が代弁する]
（例：「Claude Codeを使うべきなのはわかった、でも一人で立ち上げる自信はない」）

[「AI家庭教師」というサービス名と、その意味の説明]
（例：中学生の家庭教師がわからない問題を一緒に解くように、
社長が「これ、AIにどう頼めばいいのか」と迷った時に相談できる）

[サービスの概要 1〜2文]
（例：週1回のオンライン面談と、Slackでのいつでも質問可能な環境で、
3か月で経営者をAIネイティブに育てる）

[最初の一歩：無料相談 30分]
[Calendly URL]
```

このブロックは **記事を売りで終わらせない** 工夫が肝。「経営者の本音を代弁する」段落から始めると、自然に流れる。

---

参照する書き手の方向性：

- **林修**：歴史と古典で知的厚みを出す。「なぜそうなるのか」を読者に追わせる。決め台詞で締める。
- **池上彰**：そもそも論から入る。専門用語を即座に言い換える。子どもにもわかる例えで本質に迫る。
- 北野唯我・山口周・馬田隆明・入山章栄・安宅和人：論点の構造化、フレームワーク、引用の効果的活用

本ルールは、これらの書き手の **共通項** を抽出し、桜木さんの記事執筆に落とし込んだ実務ガイドです。

## 第0.5章：読者ターゲットと「文系過ぎない」調整

### 0.5-1. 読者は誰か

このシリーズの読者は **中小企業経営層・個人事業主** である。具体的には：

- 社員数 1〜30 名の会社のオーナー社長
- 士業（税理士・社労士・コンサルなど）
- 年商 3,000 万〜10 億円規模の経営者
- 自分の時間と利益を最大化したいと考えている人

この層が日常で使う言葉と、関心を持つ話題に寄せる。

### 0.5-2. 「文系過ぎる」表現を避ける

林修・池上彰スタイルを踏襲しつつも、**文学的・歴史的な脱線が長い記事は、中小企業経営層には響きにくい**。以下を意識する：

避けるべき：
- 古典・哲学への長い言及（孔子、ニーチェ、ドラッカーの長い引用など）
- 文学的な比喩を連発（「庖丁のような〜」を全段落で使うなど）
- 林修の決め台詞オマージュ（「いつやるか？今でしょ」を毎回使う）
- 江戸時代・明治時代への長い遡り
- 「人間とは何か」「学びとは何か」のような抽象的な問いかけ

推奨：
- 業界事例（フィルムカメラの衰退、ストリーミングの台頭など、ビジネス史の範囲）は1記事1個まで
- たとえ話は **読者の業務に近いもの**（飲食店のオーダー、士業の顧問先対応、製造業の在庫管理など）
- 数字・時間・利益の話を中心軸にする
- 競合・市場・社員といった経営者の関心ワードを散りばめる

### 0.5-3. 経営者が刺さる語彙

中小企業経営層が反応しやすい語彙：

- 時間：「月30時間」「週末がまるごと空く」「朝の15分」
- 利益：「人件費を削らず効率化」「秘書1人雇う代わりに」
- 競合：「同業他社が動き始めている」「3年遅れると追いつけない」
- 社員：「号令だけでは社員は動かない」「社長の背中を見せる」
- 顧客：「常連さんのために」「最後の出口で関係を作る」
- リスク：「やらないリスク」「待つコスト」

これらの語彙を、論点の中で自然に使う。文系的な「人間性とは」「成長とは」よりも、業務直結の言葉で語る。

## 第1章：林修・池上彰スタイルの本質

### 1-1. 二人の共通項

林修・池上彰の解説には、読者を引き込む共通の構造がある。

- **「実は」「ところが」「ここが面白いのですが」で読者の予想を裏切る**
- **専門用語を出した直後に、子どもにもわかる例えで言い換える**
- **歴史的経緯を1〜2行で挿入し、知的奥行きを出す**
- **読者の疑問を先回りして言語化する**（「ここで、ある疑問が浮かびます」）
- **「なぜか」「どういうことか」を畳みかけて、論理を一歩ずつ進める**
- **結論を先に出さない**。読者と一緒に考える形で進める
- **上から目線にならない**。「私は」「私たちは」で並走する
- **数字は単独で出さず、必ず文脈と一緒に**

### 1-2. 林修スタイルの特徴

- **歴史・古典への目配り**：「これは、実は江戸時代から〜」「孔子もこう言っています」
- **対比の妙**：「Aかと思いきや、Bだったんです」
- **決め台詞で締める**：「いつやるか？今でしょ」「結局、◯◯なんです」
- **読者を賢い人として扱う前提**：説明しすぎない。考えさせる余地を残す

### 1-3. 池上彰スタイルの特徴

- **そもそも論から入る**：「そもそも、AIとは何か」
- **専門用語を即座に翻訳**：「これを業界では『◯◯』と言いますが、要するに〇〇のことです」
- **質問形式で進める**：「なぜそうなるのでしょうか」「ここで、ある疑問が浮かびます」
- **数字を文脈と一緒に出す**：「5倍と聞くと驚くかもしれませんが、内訳を見ると〜」
- **結論ではなく理解を届ける**：「だから、こう動きましょう」より「だから、こうなっているわけです」

## 第2章：難解な言葉・カタカナ語の排除

### 2-1. なぜ排除するのか

カタカナ語と専門用語は、書き手にとっては便利だが、読者を疎外する。林修・池上彰の解説には、カタカナ語がほとんど出てこない。出ても、その瞬間に日本語に翻訳される。

桜木さんが「難しいことをやさしく」と口癖にしている以上、これは文体の要である。

### 2-2. 出したら即翻訳する語のリスト

以下の語は、本文で使う場合、**必ず直後にカッコで日本語の言い換えを添える**。2回目以降は日本語のみで通す。

| カタカナ語 | 日本語の言い換え |
|---|---|
| AX | AIによる仕事のやり方の作り直し |
| DX | デジタル化／パソコン・ネットによる効率化 |
| AIネイティブ | AIを当たり前に使える状態 |
| フルコミット | 全力で取り組む |
| ラストワンマイル | 最後の1区間／最後の出口 |
| エンパワーメント | 力を引き出す／後押しする |
| アウトプット | 成果／仕事量 |
| パフォーマンス | 能力／成果 |
| イノベーション | 革新／新しい価値の創造 |
| ロードマップ | 進め方の道筋 |
| インプリメンテーション | 実装／実際にやってみること |
| フレームワーク | 考え方の型／枠組み |
| エコシステム | 仕組み全体／生態系 |
| ビジョン | 目指す姿／構想 |
| コミットメント | 約束／本気で取り組む姿勢 |
| シナジー | 相乗効果 |
| バリュー | 価値 |
| ソリューション | 解決策 |
| アジェンダ | 議題／論点 |
| ステークホルダー | 利害関係者／関わる人たち |

### 2-3. 排除すべき難解な漢語

以下のような硬い漢語も、可能な限りやさしく言い換える：

- 「示唆」→「ヒント」「気づき」
- 「敷衍」→「広げて言うと」
- 「俯瞰」→「全体を見渡す」
- 「漸進的」→「少しずつ」
- 「画期的」→「いままでにない」（あるいは削除）
- 「本質的」→「根っこの部分」（連発しない）
- 「象徴的」→「典型的な」（連発しない）

ただし、引用文の中の語は変えない。引用は引用として尊重する。

## 第3章：知的好奇心を刺激する書き方

### 3-1. 「実は」「ところが」「ここが面白いのですが」を使う

読者の予想を裏切る接続詞は、知的好奇心の最大のエンジンだ。

- 「DXとAXは、似ているように見えます。**ところが**、根本的に別物なんです」
- 「5倍と聞くと、驚く数字に見えます。**実は**、内訳を見ると納得できます」
- 「**ここが面白いのですが**、秋好CEOは趣味の釣りでもAIを使っています」

ただし、1記事に5回以上連発すると安っぽくなる。3〜4回までを目安に。

### 3-2. 歴史・身近な例えで地に落とす

抽象的な概念を出した後、必ず歴史的な事例か、日常の身近な例えで補強する。

- 抽象：「業界に乗り遅れると生き残れません」
- 補強：「フィルムカメラの会社がデジタルに乗り遅れて消えました。レンタルビデオ屋がストリーミングに食われました。同じことがAIでも起きます」

- 抽象：「AIに任せる仕事と、人間が向き合う仕事を分けるべきです」
- 補強：「『ラストワンマイル』という言葉、聞いたことがあるでしょうか。物流の業界用語で、トラックで運ぶ部分は機械的にできるが、最後にお客さんの玄関先まで届ける1区間だけは人の手が必要、という意味です」

### 3-3. 読者の疑問を先回りする

読者が抱きそうな疑問を、書き手が先に言語化する。

- 「ここで、ある疑問が浮かぶかもしれません。なぜ社長が、自分のAI使用を株主の前で宣言するのか？」
- 「『5倍、10倍』と聞くと、本当か、と思う方も多いと思います。正直に言うと、私もそう思いました」

これだけで、読者は「自分の気持ちをわかってくれている」と感じる。

### 3-4. 結論を先に出さず、一緒に考える

林修・池上彰スタイルは、結論を結論として押し付けない。読者を一緒に思考の旅に連れて行く構造を取る。

- NG：「経営者は、AIネイティブになるべきです。理由は3つあります」（押し付け型）
- OK：「では、なぜ経営者が、自分でAIを触らなければいけないのか。実は、塾の先生にたとえるとわかりやすいんです」（並走型）

### 3-5. 決め台詞・印象的な締めくくり

林修の「いつやるか？今でしょ」のような、印象的な締めの一行を、記事に1つ入れる。ただし、毎回同じ型は飽きるので、以下のバリエーションを使い分ける：

- 問い返し型：「いつやるか？今でしょう」
- 断定型：「結局、自分で触ったかどうか、それだけなんです」
- 余韻型：「3,000円と、寝る前の一回の対話。それで十分です」

## 第4章：AI書きの典型的シグナル（やってはいけないこと）

桜木既存記事 `02_akiyoshi_ai.md`（旧版）の分析と、生成AIが書きがちな文章の特徴から、以下を **絶対NG** と定める。

### 4-1. 構造のNG

- **「検証済み引用①〜⑥」のような機械的番号付け見出し**
- **「｜（縦棒）」を使った二段見出しを連発**（1記事3回以上）
- **「はじめに｜なぜ◯◯から学ぶのか」型の見出し**
- **架空ペルソナ（Aさん／Bさん／Cさん）を3人並べる**
- **「⚠️ 以下は架空のシナリオです」のような注記**
- **「桜木さんへ｜公開時の確認事項」「TODO」「[ ]」が本文末に残る**

### 4-2. 文末・語彙のNG

これらの語が出たら、書いた直後に消す：

- 「すべてを物語っています」
- 「衝撃的な数字です」
- 「これは……への重要な問いかけです」
- 「設計思想そのもの」
- 「本質」「核心」「象徴」を **同一記事に複数回**（1回までなら可）
- ロングダッシュ「——」を1記事に5回以上

### 4-3. 装飾のNG

- **絵文字（🎓📦✉️✅⚠️）を本文・見出しに入れる**
- **太字を1段落に2回以上連続**
- **矢印＋未来予言太字**「→ **3か月後、あなたは◯◯になっています**」
- **数値・固有名詞を太字にする**

## 第5章：王道ビジネス解説の構造

### 5-1. 記事の典型構造

以下の7ブロックで構成する：

1. **タイトル**（記事の価値を明示）
2. **導入**（誰のための記事か、なぜ重要か、何が学べるか、300〜500字）
3. **論点1〜4**（各論点を見出しで区切り、500〜1000字で解説）
4. **補足**（関連する興味深い視点、200〜400字）
5. **まとめ**（論点を再整理、実装指針に落とす、300〜500字）
6. **出典**（信頼性を担保）
7. **著者情報**（短く）

各論点は、**「身近な例えや歴史で導入 → 引用 → 解説 → 読者の疑問への先回り → 実装への翻訳」** の流れを取る。

### 5-2. 見出しの型

見出しは **「論点◯：（読者の素朴な疑問を含む短いフレーズ）」** の形式が、知的好奇心と網羅性を両立する。

OK例：
- 「論点1：『AX』とは何か。なぜ今これが大事なのか」
- 「論点2：AIに任せる仕事と、人間がやる仕事を、どう分けるか」
- 「論点3：社長自身が、誰よりも先にAIを使う」
- 「論点4：『5倍、10倍』の生産性。本当か」

NG例：
- 「## 検証済み引用①｜AX（AIトランスフォーメーション）コミット」（機械的番号）
- 「## はじめに｜なぜ秋好CEOから学ぶのか」（テンプレ感）

見出しに **問い・疑問形・素朴な感想** を入れると、読者が「先を読みたい」と感じる。

### 5-3. 引用の扱い

引用は信頼性の源泉として、**1記事に5〜10箇所** 配置する。

- 引用ブロック（`> 〜`）で明確に区切る
- 出典は記事末尾でまとめて明記（本文中の引用直後に長い出典を書かない）
- 短い引用（30字以下）は本文中に「〜」で組み込む
- 長い引用は引用ブロックで独立表示

### 5-4. 太字の使い方

太字は、**「読者がメモしておきたいキーワード／結論」** に使う。

太字を使うべき場面：
- **概念の名付け**（例：「これを **『ラストワンマイル人間化』** と呼んでいる」）
- **結論の強調**（例：「**最後の出口だけは、人間が担う**」）
- **対比の片側**（例：「全部任せるのでも、全部やるのでもなく、**最後だけ自分で**」）

禁止事項：
- 1段落に2回以上連続させない
- 矢印＋未来予言太字をやらない
- 数字・固有名詞を太字にしない（読み手は数字を勝手に拾う）
- 1記事15箇所以内に抑える

### 5-5. テーブルの扱い

**テーブルは原則として使わない**。情報を構造化したい時は、散文か箇条書きで書く。

理由：
- テーブルは生成AIが安易に使う典型パターンで、AI書き感が出る
- スマホでの可読性が低い
- 林修・池上彰の解説にも、ほとんどテーブルは出てこない

例外的にテーブルが許される場面（1記事に最大1個まで）：
- 複数項目の単純な対比（例：「言い換え一覧」のような辞書的用途）
- ステップごとの数値変化

それ以外は、**「ひとつめは〜、ふたつめは〜、みっつめは〜」のような散文構造** で書く。

### 5-6. 箇条書き

情報を3〜5項目で並列に示すときは、箇条書きを使ってよい。ただし以下に注意：

- 1記事につき箇条書きブロックは2〜3個まで
- 1項目1〜2行に収める
- 8項目以上は読者が把握しきれない（散文に分解する）
- 入れ子（ネスト）は使わない

### 5-7. フレームワーク・分類

論点を整理するためのフレームワーク（4段階モデル、3層構造など）は、**散文で説明** することを基本とする。

OK例（散文）：
> 4つの段階に分けてお話しします。
>
> 第1段階：朝のニュース整理を、AIに頼む。これだけで、毎朝15分の作業が1分になります。
>
> 第2段階：いつもやっている定型業務を、AIに任せる。議事録、提案書の下書きなどです。
>
> 第3段階：判断に迷う時、AIに相談する。論点が一気に整理されます。
>
> 第4段階：自分の業界知識を、AIに教え込む。ここまで来ると、AIが自分専用の参謀に育ちます。

## 第6章：桜木健二の文体ルール

### 6-1. 1文・1段落の長さ

- 1文は40〜80字を中心、結論文や強調文は短く（10〜30字）
- 1段落は3〜5文で改行
- 1段落で1論点に絞る

### 6-2. 文末リズム

- 基本は「です・ます」調
- 結論文や定義文は「だ・である」で引き締める（5〜10文に1回）
- 「〜なのです」「〜と言えるでしょう」「〜のではないでしょうか」を1記事3回以下に
- 体言止めは1記事3回まで

### 6-3. 数字の出し方

数字は、**必ず文脈と一緒に出す**。単独で投げ出さない。

- NG：「生産性が500%向上」
- OK：「生産性が5倍。たとえば、月40時間の雑務が8時間に減るような変化です」

### 6-4. 「私（桜木）」の出し方

- 自分の見解は、論点解説の中盤や終盤に1〜2行で挿入
  - 例：「私の経験では、ここで多くの経営者がつまずきます」
- クライアント事例は1記事1人まで（複数並べると架空ペルソナ感が出る）
- 経歴（東大近山研／元塾講師）は1記事1回まで

### 6-5. 読者への呼びかけ

- 「あなた」を多用しない（説教調になる）
- 「経営者の方は」「私たちは」「読者は」のように **集団主語** にする
- ただし、内省を促す場面では「ここで、自分の仕事を頭に並べてみてください」のように軽く呼びかける

### 6-6. 接続詞のリズム

林修・池上彰スタイルの肝は、接続詞のリズムにある：

- **「ところが」「実は」「ここが面白いのですが」**で予想を裏切る
- **「なぜか」「どういうことか」**で論理を進める
- **「たとえば」「具体的には」**で身近に落とす
- **「つまり」「要するに」**で締めくくる
- **「しかし」「ただし」**で例外を提示する

これらを意識的に使うだけで、文章に呼吸が生まれる。

## 第7章：記事のひな形

### 7-1. タイトル

```
◯◯氏が語った「◯◯◯◯」の中身｜
〜が今知っておくべき◯個のこと
```

または

```
なぜ◯◯なのか｜〜が読み解く◯◯の構造
```

### 7-2. 導入（300〜500字）

```
[誰の発言／何が起きたか]（2〜3文）
[なぜそれが珍しい・重要か（読者の知的好奇心を刺激する一言）]（1〜2文）
[ここで、ある疑問が浮かびます型の問いかけ]（1〜2文）
[本記事で何を解説するか]（1〜2文）
```

### 7-3. 各論点ブロック（500〜1000字）

```
## 論点◯：[読者の素朴な疑問を含む短いフレーズ]

[論点の前提を、身近な例えか歴史で導入]（2〜4文）

> 「直接引用」

[引用の解説。専門用語が出たら即翻訳]（2〜4文）

### [小見出し：その論点を一歩深める問い]

[フレームワークや段階を、散文で展開]

[筆者の見解を1〜2行]
```

### 7-4. まとめブロック

```
## まとめ：明日から始める、◯個の行動

[本記事の論点を、ひとつ／ふたつ／みっつ／よっつ、と散文で再整理]

[全体の総括メッセージ]

[筆者の体感・実例を1〜2文]

[最初の一歩の提案＋林修風決め台詞]
```

## 第9章：トーンサンプル

### サンプル1：導入（300〜500字）

> ランサーズ株式会社の社長、秋好陽介さんが、2025年5月の決算説明会で、AIに対する考え方をはっきりと述べました。
>
> ランサーズと言えば、フリーランスや個人事業主の働き方を支える会社です。その会社のトップが、決算説明会という場で、AIをこう使う、こう変える、と具体的に話したわけです。
>
> ここに、面白いことがあります。
>
> 普通、決算説明会は業績の数字を読み上げる場です。ところが秋好さんは、「自分自身がAIを使う」という、極めて個人的な話までしました。これは、ちょっと珍しいことなんです。
>
> なぜ社長が、自分のAI使用宣言を、株主の前でしたのか。
>
> そこにこそ、これからの経営者が読み取るべきメッセージがある、と私は考えます。本記事では、秋好さんの発言を4つの論点に整理しながら、小さな会社のオーナーが今すぐ何をすべきか、お話しします。

### サンプル2：論点解説の冒頭（身近な例えで導入）

> ## 論点2：AIに任せる仕事と、人間がやる仕事を、どう分けるか
>
> 秋好さんの発言の中で、私がいちばん大事だと思っているのが、これです。
>
> > 「AIでできるところはAIでいいよ、もしくはAIでできない人間しかできないところのラストワンマイルを人間でやってほしい」
>
> 「ラストワンマイル」という言葉、聞いたことがあるでしょうか。
>
> これは、もともと物流の業界用語です。商品を運ぶ時、東京から大阪までトラックで運ぶ部分は機械的にできます。ところが、最後にお客さんの玄関先まで届ける、その「最後の1区間」だけは、どうしても人の手が必要になる。これを「ラストワンマイル」と言います。
>
> 秋好さんは、この言葉をAIの議論に持ち込んだわけです。

### サンプル3：散文でのフレームワーク提示

> ### では、社長はどこから始めればいいか
>
> 「AIを使え」と言われても、何から始めればいいかわからない。これが、ほとんどの経営者の本音です。
>
> 4つの段階に分けてお話しします。
>
> 第1段階。朝のニュース整理を、AIに頼みます。毎朝15分かけていた作業が、1分で終わるようになります。ここで、まず「あ、本当に楽になる」という体感を得ます。
>
> 第2段階。いつもやっている定型業務、議事録や提案書の下書き、SNS投稿などをAIに任せます。1か月続けると、月に30時間ほど時間が浮きます。
>
> 第3段階。判断に迷う時、AIを「壁打ち相手」として使います。論点を整理してもらうだけで、意思決定の質が上がります。
>
> 第4段階。自分の業界知識をAIに教え込みます。ここまで来ると、AIが「自分専用の参謀」に育ちます。

### サンプル4：まとめ（散文＋決め台詞）

> ## まとめ：明日から始める、4つの行動
>
> ここまでの話を、一度まとめておきます。
>
> ひとつ。AIによる仕事のやり方の変化は、もう始まっています。3年遅れると、業界の風景が変わってしまっている。今、動き始める価値があります。
>
> ふたつ。仕事を「AIに任せるもの」と「自分にしかできないもの」に分けて、紙に書き出す。これだけで、3か月後の働き方が変わります。
>
> みっつ。社長自身が、誰よりも先にAIを使う。号令ではなく、自分の手で触ることから始める。
>
> よっつ。3か月で2倍を取りに行き、半年で3〜5倍、1年で5〜10倍を目指す。最初から大きな数字を狙うと、ほぼ折れます。
>
> 私自身も、毎朝Claudeに話しかけることから始めて、3か月で月に30時間を取り戻しました。最初の一歩は、月3,000円のClaude Pro契約と、寝る前のたった一回の対話で十分です。
>
> 「いつやるか？」
>
> 少なくとも、今でしょう。
