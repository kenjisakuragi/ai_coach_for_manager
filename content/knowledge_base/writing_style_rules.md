## 1. 問題記事 `02_akiyoshi_ai.md` の分析｜なぜ「AI書き」に見えるのか

### 1-1. AI書きシグナル（具体的に検出）

- **太字の濫用**：1記事で太字が約40箇所以上。1段落に2回以上太字が出る箇所も多数。例：「**個のエンパワーメント**」「**AIネイティブ経営**」「**フルコミット**」「**設計思想そのもの**」「**核心**」が連続。読み手は「強調が強調にならない」状態になる。
- **「検証済み引用①〜⑥」という機械的な番号付き定型構造**：人間の書き手は「①検証済み引用」とは絶対に書かない。社内資料・コンプラチェックリストの匂い。
- **「——これらが重なる」「——」のロングダッシュ多用**：1記事に7回以上。LLMの典型的な接続癖。
- **絵文字＋見出し**：「🎓 AI駆動経営 導入パッケージ」「📦 2時間個別レッスン」「✉️ 無料相談」「✅ この記事は安全に公開できます」。営業ページと社内チェックリストが混在しているノイズ。
- **テーブルでの「Before/After」整理**：業務／AIに任せる／人間で向き合う、の3列テーブル。生成AIが「整理してください」と言われて真っ先に作る型。
- **見出し階層の固さ**：「## はじめに｜なぜ秋好CEOから学ぶのか」「## 検証済み引用①｜……」のように、すべての見出しが「｜（縦棒）でタイトル＋サブタイトル」型。テンプレ感が強い。
- **「3つの実装方法」「3つのこと」「3か月で」と数字に丸めすぎ**：3点リスト依存症。
- **「→ **3か月後、あなたは "AIネイティブ経営者" になっています。**」のような矢印＋断言の太字結語**：LLMが「結論を強調する」ときの典型ムーブ。
- **誇張ワードの羅列**：「衝撃的」「最も印象的」「すべてを物語っています」「核心」「本質」「象徴」。この6語が同じ記事内に登場する人間はあまりいない。
- **架空シナリオの作り込み**：「Bさん 39歳 年商3,500万→5,500万（1.5倍）」と数字付きペルソナ。ご丁寧に「⚠️ 以下は架空のシナリオです」と注記まで付ける。リスク回避ロジックが文章に染み出している。
- **末尾の「桜木さんへ｜公開時の確認事項」セクション**：これは記事ではなくAIアシスタントから本人へのToDo報告。本来は記事の外に置くべきもの。**ここが残っているだけで「AIが書いた下書きをそのまま出した」と即バレる**。
- **チェックボックス`- [ ]`を本文に残している**：これも作業メモ流出の典型。
- **引用の出典書式が論文風**：「（2025年5月14日登壇／2025年5月20日公表）」と日付の二重表記。読み物としては過剰。
- **すべての段落が「結論→根拠→翻訳」の3段リズムで均一**：人間の文章にはもっとブレがある（脱線、自問、急に話題が飛ぶなど）。

### 1-2. 人間の文章として「足りない」もの

- **個人的な失敗譚・恥ずかしいエピソード**がゼロ。秋好CEOの引用ばかりで、桜木さん本人が「自分はこう失敗した」「最初のクライアントでこんなドジを踏んだ」が一切ない。
- **迷い・揺らぎ**がゼロ。「正直、最初はこの言葉に違和感があった」「でも実際にやってみたら見方が変わった」のような心の動きがない。
- **塾講師時代のエピソード**がゼロ。「東大近山研出身・元塾講師」というキャラ設定が文章に1ミリも反映されていない。
- **固有名詞の生っぽさ**がない。「私のクライアントの飲食店オーナーAさん」「先週の壁打ちで」のようなディテールがゼロ。
- **文末リズムの揺らぎ**がない。全文「です・ます」で、句点の前の語感がほぼ均一。
- **読者への問いかけ**が最後の1回しかなく、しかも「あなたは AI ネイティブになる準備ができていますか？」と説教調。
- **自分の体温**がない。「眠い朝に Claude にぼやいた」「これを書いてる今、隣でコーヒーが冷めている」のような身体性ゼロ。

## 2. 人気note著者から観察した執筆パターン（実観察ベース）

### 2-1. 深津貴之（fladdict）— 観察3記事

**冒頭の入り方が現場観察＋一言で揺さぶる**

- 「わりと複数の企業のお悩みが、『**そもそも生成AIでやるべきでない問い**』にチャレンジして疲弊してる」（観察→問題提起）
- 「『生成AIDXちゃんとやってるよ！』といいながら、ビジネスインパクトの小さい細かい作業のAIばかり作っていませんか？」（修辞的問いかけ）

→ いきなり結論を太字にするのではなく、「現場で観たこと」を素描してから本題に入る。

**1文の長短のリズム**

短文：「ヤバい。」「我々マネジメント層のほうが、あとがないんですね。」
長文：「経営判断は『全体感』が求められ、執行は『細部の完璧性』が求められるからです。」

→ **3〜5文に1回は超短文を投下**して呼吸を作る。

**太字は「概念の名付け」だけに絞る**

「**そもそも生成AIでやるべきでない問い**」「**全体感が正しければ成果になる仕事**」のように、一度名付けたフレーズを以降太字で再出現させる。**1段落に太字は最大1箇所**が基本。

**文末のひねり**

「現場を無人化するまえに、イケてない取締役に不信任決議案を提出するAIを作る…ぐらいの気分で経営はAIDXを進めていきましょう。」

→ ユーモアと軽い毒で締める。締めの太字断言ではない。

**自分語りは控えめだが「自分はこう分けて考えてる」が必ず1回は入る**

「自分はAIDXで導入するAIを…と分けて考えている」のように、論考の途中で**主語を「自分は」に切り替えて視点を提示**する。

### 2-2. 尾原和啓（kazobara）— 観察1記事＋プロフィール

**冒頭が「会話の続き」のように始まる**

「毎日使ってるツール変わってます」「この3週間だけでも相当やばい」

→ 完成された結論ではなく、**いま喋ってる感**から入る。

**見出しが章立て＋副題のダッシュ**

「第1章：Claude、Codex、Grok──今この瞬間のツール布陣」
「第2章：Claude Cowork の進化──『心拍』が変えた自律AI」

→ 「今この瞬間」「変えた」など**動きのある語**を必ず副題に入れる。

**自分を三人称（「尾原は」「尾原が」）で呼ぶ**

これは尾原氏特有のクセ。マネはしなくていいが、**自分のキャラ名を文章に固有名詞として登場させる**のは「中の人感」が出てよい。

**結びの文が哲学的で短い**

「特定のツールへの執着ではなく、変化に乗り続ける『サーファー的姿勢』こそが求められる」

→ 行動指示ではなく、**比喩で締める**。

**読者への呼びかけは控えめだが、最後にPodcast/フォロー誘導が1回だけ**

「もし、よろしければPodcast登録、フォロー、いいね　お願いします」

→ 桜木記事のように営業セクションを3つも並べない。**1記事＝1誘導**。

### 2-3. 共通して見えた黄金パターン

- 太字は1段落に最大1箇所、概念の「名付け」用途のみ
- テーブルはほぼ使わない（深津3記事、尾原1記事すべてテーブルなし）
- 絵文字は本文に使わない（タイトル絵文字も観察記事ではゼロ）
- 「✅」「📦」「🎓」のようなUI絵文字は人気著者は本文で使わない
- 結びは「断言＋太字」ではなく「比喩」「軽い毒」「自分への独り言」で抜ける
- 自分語りは多くないが、必ず1〜2回は「自分は」「私は」が混ざる
- 1記事の長さは3,000〜6,000字程度が中心（桜木記事は約5,500字でこれは適正）
- 短文（10〜20字）を意識的に挿入してリズムを作る

## 3. 桜木健二の文体ルール（実務ガイド）

### 3-1. 1文・1段落の長さ

- **1文は40〜80字を中心、たまに10字未満の超短文**を投下する。
  - NG：「秋好氏の発言が示す通り、AIネイティブ経営とは、経営者自身が誰よりも先に AI を使い、社員にもそれを広げ、組織全体として AI を前提とした業務設計を行うという、極めて統合的な経営思想であると言えるでしょう。」（一文100字超）
  - OK：「秋好氏の言葉でハッとした。経営者が一番に使えばいい。それだけだった。」
- **段落は3〜5文で改行**。連続で長段落を続けない。
- 1段落ごとに必ず句点が3〜5個入るくらいに抑える。

### 3-2. 太字の使用基準

- **1記事につき太字は10箇所まで**（桜木既存記事は40+で完全にオーバー）。
- 太字は「**概念の名付け**」だけに使う。例：「**ラストワンマイル人間化**」のように、自分が名付けた語に対してのみ。
- **断言の結語を太字にしない**。「**3か月後、あなたはAIネイティブ経営者になっています**」のような未来予言太字は禁止。
- 数値・固有名詞は太字にしない（読み手は数字を勝手に拾う）。

### 3-3. 見出し

- **「｜（縦棒）」を使った二段構成見出しを乱発しない**。1記事で2回以下。
- 見出しに**動詞・問い**を入れる。
  - NG：「## はじめに｜なぜ秋好CEOから学ぶのか」
  - OK：「## ランサーズの決算で、僕の手が止まった」
  - OK：「## 「AIに任せる」って、結局どこからどこまで？」
- 「検証済み引用①」「検証済み引用②」のような**機械的番号付け禁止**。

### 3-4. 書き出しの型（オープニング3パターン）

**型A：身体・現場の描写から入る（深津型）**
> 先月、大阪のとあるカフェオーナーさんと壁打ちをしていた時のことだ。「桜木さん、AI使えって言われるけど、何から手をつけたらいいの？」——その一言で、僕は1時間しゃべりすぎた。

**型B：自分の失敗・恥から入る（塾講師型）**
> 塾講師をしていた頃、僕は「わかりやすく教える」のが下手だった。難しい問題を、難しいまま「これは入試によく出ます」と言ってしまう。生徒の目が死ぬ。あの頃の苦さを、今 Claude を経営者に教える時にも思い出す。

**型C：相手の発言を借りて入る（尾原型）**
> 「毎日使ってるツール変わってます」——尾原和啓さんがそう言っていた。正直、最初は煽りに見えた。でも自分でも3週間で2回乗り換えた今、笑えない。

→ **どの型でも、3行以内に「桜木自身の体温」を入れる**。

### 3-5. 自分語りの密度

- **3つの見出しごとに、最低1回は「自分の小さな具体エピソード」を入れる**。
  - クライアント名は架空でいい（「飲食店オーナーのKさん」など）が、**一人だけに絞る**。Aさん・Bさん・Cさんと並べると途端にフィクション臭くなる。
  - 1エピソード＝具体物が1つ（コーヒー、ホワイトボード、深夜のSlackなど物質を出す）。
- **「東大近山研」「塾講師」を出すのは1記事1回まで**。出しすぎると経歴自慢に見える。

### 3-6. 「難しいことをやさしく、やさしいことをふかく」の文体反映

桜木さんの口癖を実装するには：

- **専門用語を出した直後に、ひらがなで言い換える**。
  - 例：「AXトランスフォーメーション、つまり『仕事のやり方をAI前提で組み直すこと』ですね。」
- **やさしい言葉で書いた後に、もう一段ふかく掘る**。
  - 例：「『AIに任せる』って言うと簡単に聞こえる。でも本当の難所は、任せた結果を自分が信じられるかどうかだ。」
- **「〜と言えるでしょう」「〜のではないでしょうか」を避ける**。塾講師は断定するか、問い返す。「〜です。」「〜ですか？」で切る。

### 3-7. 文末リズム

- 「です・ます」基調で、**5〜10文に1回「だ・である」を混ぜる**と引き締まる。
  - 「これは経営者だけの話じゃない。社員一人ひとりの話だ。」
- 「〜なのです」「〜と言えるでしょう」を**1記事3回まで**。
- **体言止めは1記事3回まで**。やりすぎるとブログ感（広告感）が出る。

### 3-8. 読者への呼びかけ

- 「あなた」「みなさん」を**本文では基本使わない**。読者は呼びかけられると引く。
- 代わりに「僕ら」「経営者って」「中小企業の現場で」のように**主語を集団に**する。
- 呼びかけが必要なのは結びの1〜2回まで。

### 3-9. 禁止リスト（NGワード集）

以下は、出てきたらAI臭がするので**書いた直後に消す**：

- 「すべてを物語っています」
- 「核心」「本質」「象徴」（同じ記事に複数出るとアウト）
- 「衝撃的な数字です」
- 「これは……への重要な問いかけです」
- 「→ **〜になっています。**」（矢印＋未来形断言太字）
- 「①検証済み」「②検証済み」のような番号ラベル
- 「設計思想そのもの」
- 「フルコミット」を引用以外で使う
- 絵文字（🎓📦✉️✅⚠️📦）を本文・見出しに入れる
- ロングダッシュ「——」を1記事5回以上

### 3-10. テーブル・箇条書き・絵文字

- **テーブルは原則使わない**（観察した深津・尾原記事はゼロ）。どうしても比較が必要なら散文で書く。
- **箇条書きは1記事につき2ブロックまで**。3つ以上はリスト過多。
- **絵文字は本文・見出しに使わない**。例外：商品紹介ブロックを最後に1か所まとめる場合の小見出しのみ可（ただし禁欲的に）。

## 4. 記事のひな形

### 4-1. オープニングの型（200〜400字）

```
【1】身体・現場・固有名詞のディテール（2〜3行）
   → 「先週、〇〇な状況で、〇〇さんがこう言った」
【2】桜木の小さな反応（1〜2行）
   → 「正直、最初はピンとこなかった」「思わず手が止まった」
【3】この記事で何を書くかを軽く宣言（1行）
   → 「今日はその時に考えたことを書きます」
   ※「3つの〇〇を解説します」型の宣言は使わない
```

### 4-2. 論を進める型（中盤の繰り返しユニット）

```
【見出し（動詞か問い）】
段落1：エピソードか引用（具体物アリ）
段落2：そこから僕が考えたこと（「自分は」を入れる）
段落3：塾講師っぽい言い換え or 反対意見への目配り
段落4：「だから〇〇なんですよね」と一拍置いた結語（断言しすぎない）
```

これを2〜4ユニット繰り返す。

### 4-3. 結びの型（150〜300字）

3パターンから選ぶ：

**型X：比喩で抜ける（尾原型）**
「結局、AIは庖丁と同じだ。切れ味の良い庖丁を手にしたからって、料理人になれるわけじゃない。毎日握って、自分の手に馴染ませた人だけが、ようやく『使える』と言える。」

**型Y：軽い毒・自嘲で抜ける（深津型）**
「とか偉そうに書いておいて、僕も先週 Claude に同じプロンプトを3回入れて違う答えが返ってきて頭を抱えた。AIネイティブへの道は遠い。」

**型Z：一行で問い返す（塾講師型）**
「『難しいことをやさしく、やさしいことをふかく』。今日のこの話、あなたの現場ではどっちにあたるだろう。」

→ **どの型でも、サービス紹介・CTA・引用元再掲は結びの後に別ブロックで分離**する（本文と混ぜない）。

### 4-4. CTA・サービス紹介のブロック

- 本文の最後に**水平線`---`を入れて、明確に切る**。
- サービスは**3つ並べない**。1メイン＋1サブまで。
- 絵文字は使わないか、使っても1個まで。
- 「桜木さんへ」「公開時確認事項」のような**作業メモは絶対に本文に残さない**（別ファイルにする）。

1. [ ] 太字が10箇所以下か（カウントせよ）
2. [ ] 見出しに動詞か問いが入っているか
3. [ ] 「｜」二段見出しは2回以下か
4. [ ] 「①」「②」のような機械的番号ラベルがゼロか
5. [ ] 本文中の絵文字（🎓📦✅⚠️など）がゼロか
6. [ ] テーブルがゼロ、または1個までか
7. [ ] ロングダッシュ「——」が4回以下か
