# Claude Code経営活用事例 #05｜楽天三木谷会長の場合

このシリーズでは、有名経営者の公開発言を題材に、**中小企業のオーナーが Claude Code を経営にどう取り入れるべきか** を読み解きます。

第5回は、楽天グループ株式会社 代表取締役会長兼社長の三木谷浩史さんです。

楽天と言えば、楽天市場で5万を超える出店者（ほとんどが中小事業者）を抱える、日本最大級のEC基盤を運営する会社です。その三木谷さんが、2025年1月31日に開催された「楽天新春カンファレンス2025」で、リアル会場約2,700人・オンライン約3万人を前に、AIに対する考え方を**かなり強い言葉で**示しました。

ここに、面白いことがあります。

普通、新春カンファレンスというのは、その年の販促キャンペーンの紹介や売上目標の発表で終わるものです。ところが三木谷さんは、楽天市場店舗の皆さんに向けて、こう言い切ったのです。

> 「AI（人工知能）を使いこなせない企業は未来が厳しくなる」

さらに踏み込んで、こう続けました。

> 「店舗の皆さんもこのAIを最大限活用しないといけない」

楽天市場の出店者は、ほとんどが社員数名から数十名の中小事業者です。そこに、楽天グループのトップが「AIを使えない企業に未来はない」と直接呼びかけた。これは、シリーズ過去回の秋好CEO、南場会長、高野氏の発言とも違う、**ターゲットの近さ** が際立つメッセージなのです。

なぜ三木谷さんは、自社のサービス売り込みではなく「あなたが使えるかどうかが問題だ」と店舗に語ったのか。

そこにこそ、楽天市場の外側にいる中小企業のオーナーが読み取るべきメッセージがあると、私は考えます。本記事では、三木谷さんの発言を4つの論点に整理しながら、社員5〜30人規模の経営者が今すぐ何をすべきか、お話しします。

---

## 論点1：「No AI, No Future」とは何を意味するか

三木谷さんが新春カンファレンスで掲げた標語は、強烈な4語でした。

> No AI, No Future.

これは、各種報道のヘッドラインでも繰り返し使われた言葉です（出典：日本ネット経済新聞、ECのミカタ、ITmedia など）。

実は、似たような言葉を、私たちは過去にも聞いたことがあります。

それが「No Music, No Life」です。タワーレコードの広告コピーですね。「音楽がない人生は、人生じゃない」というメッセージで、20年以上前から使われてきました。

三木谷さんは、これと同じ構造を「AIと未来」に当てはめた。**「AIなき会社に、未来はない」**。これだけ強い言葉を、楽天市場店舗の前で口にしたわけです。

ここで、ある疑問が浮かびます。

「自分も AI を使ったほうがいい、というのはわかった。でも、なぜそんなに強い言葉で言うのか？ ChatGPTを少し触れば、それで十分じゃないのか？」

これに対する、三木谷さん自身の答えは、別の発言にあります。

> 「AI を使いこなせなくなると、どうしても人の頭脳は衰退していくんだと思う」（出典：ITmedia）

これは大事なことを言っています。

「AI を使うと頭が鈍る」のではなく、「使いこなせない側に回ると、頭が衰えていく」と言っているのです。AIを触っている同業者と、触っていない自分の差が、毎月毎月、複利のように開いていく。3年経った時、その差は埋められなくなる。

私の経験でも、これは正しい。Claude Code を触り始めた経営者と、触っていない経営者では、**判断のスピードと、選択肢の広さ** が、半年で目に見えて変わります。「AI が代わりにやってくれる」のではなく、「AI と一緒に考えていると、自分の思考の解像度が上がる」のです。

「No AI, No Future」は、煽り文句ではない。三木谷さんの実感としての警告です。

---

## 論点2：「使いこなす」の正体——三木谷さんが店舗に求めていること

新春カンファレンスで、三木谷さんが何度も繰り返した言葉があります。「使いこなす」です。

> 「皆さんが、いかにAIを使いこなせるようになるか。それをグループ全体で考えていきたい」（出典：ECのミカタ）

> 「人が、どうやって『AIを使いこなすのか』が重要だ」（出典：日本ネット経済新聞）

ここが面白いのですが、三木谷さんは「楽天が用意したAIを使いましょう」ではなく、**「あなた自身が使いこなせるようになりましょう」** と言っているわけです。

主語が、楽天ではなく、店舗側にある。

なぜか。それは、AIを「自社の業務に当てはめる」作業は、ツール提供側にはできないからです。

たとえ話で考えてみます。

包丁を作るのは、包丁職人の仕事です。けれども、その包丁で何を切るか、どんな料理を作るかは、料理人の仕事です。包丁職人がいくら良い包丁を作っても、料理人が振るわなければ、料理にはなりません。

楽天が用意するAIは、包丁です。三木谷さんが言っているのは、「包丁は用意した。あとは、あなたが使いこなしてくれ」ということなのです。

では、「使いこなす」とは具体的に何か。

私は、3つの段階に整理できると考えています。

第1段階。**自分の業務を、AIが理解できる形で言語化する**。これが意外と難しい。「うちの店は常連さん中心なので」と話すだけでは、AIは動けません。「常連さんとは、過去6か月以内に3回以上来店した方」のように、定義を一段階下げる作業が必要です。

第2段階。**自分の判断癖を、AIに教え込む**。「私は、人柄重視で採用する」「値段交渉はしない」といった、自分だけの判断パターンを、AIに登録します。これによって、AIの提案が「あなたの会社用」に最適化されます。

第3段階。**AIの出力を、自分の判断と摺り合わせる習慣を作る**。AIが出したものを、そのまま使うのではなく、「ここはOK、ここは違う」と毎回判定する。この摺り合わせを通じて、AIは育ち、自分の判断も鋭くなっていきます。

「使いこなす」とは、AIを賢く操る、という意味ではない。**AIと自分の対話の中で、自社の業務を再定義していく** ことなのです。

## 論点3：トリプル20を、自社に翻訳する方法

三木谷さんは、新春カンファレンスで「トリプル20」という具体的な目標を提示しました（出典：ECのミカタ、ケータイWatch）。

トリプル20の中身はこうです。

- マーケティング効率を 20% 向上
- オペレーション効率を 20% 向上
- クライアント（出店者）効率を 20% 向上

これら3つを、生成AIで実現する、というのが楽天グループの2025年方針です。

ところで、これは中小企業オーナーにも、そのまま使えるフレームです。

なぜか。経営の悩みを大きく分けると、ほとんどの会社で **マーケ・オペ・顧客対応** の3カテゴリに収まるからです。

たとえば、社員5名の士業事務所で考えてみましょう。

**マーケ20%効率化** とは、SNS投稿や事務所紹介資料の作成にかかる時間を、AI下書きで2割短縮することです。月10時間かけていた作業が、8時間で終わる。月2時間の創出。

**オペ20%効率化** とは、議事録、契約書のドラフト、顧問先への定例レポートなど、定型業務をAIに任せて2割減らすこと。月30時間の業務が、24時間で終わる。月6時間の創出。

**クライアント20%効率化** とは、顧問先からの問い合わせメールへの初動回答を、AIで自動下書きすること。1日10件の問い合わせが、半分の時間で対応できれば、週5時間の創出。月20時間。

合計で、月28時間。これは、社員1人を週1日早く帰らせられる規模です。年間で336時間、フルタイム社員0.2人分の労働時間を取り戻せます。

「20%」という数字を、三木谷さんは大企業の話として出しました。けれども、**経営者の業務を3つに分ける、という視点そのもの** は、中小企業のほうがむしろ効きます。社員5名の会社のほうが、業務カテゴリが見えやすく、改善のフィードバックも早いからです。

ここで、自分の業務を頭に浮かべてみてください。今週やった仕事を、マーケ・オペ・クライアントの3つに分類すると、どこに時間が一番取られていますか。

そこが、Claude Code に最初に任せるべき領域です。

## 論点4：AIエージェントが「実際の取引まで」やる時代

三木谷さんが、新春カンファレンスで踏み込んだ発言の中に、こういうものがあります。

> 「これからはAIエージェントが実際の取引までやってくれるようになる」（出典：日本ネット経済新聞）

これは、地味に見えて、相当大きな話です。

これまでのAI活用は、「下書きを作る」「要約する」「アイデアを出す」など、**人間が最後に確認する前提** の作業でした。

ところが、AIエージェントが「実際の取引までやる」となると、人間は最後の確認すらしなくていい場面が増えるということです。たとえば、定期発注、請求書の支払い、簡単な見積もり返信、予約確定など、定型的な取引業務は、AIが完結させる。

中小企業の経営者にとって、これは何を意味するか。

ひとつの解釈は「やった、楽になる」です。確かに、楽になります。

ところが、もうひとつの解釈があります。それは、**「AIエージェントを設計できる経営者と、できない経営者の差が、急激に開く」** ということです。

AIエージェントは、勝手に賢くなるわけではありません。「どういう条件で、どこまで自律的に判断していいか」を、経営者が事前に決めておく必要があります。たとえば、「3万円以下の発注は AI が自動承認、それ以上は私の確認」のような閾値設定です。

この閾値を、自分の会社の業務に合わせて設計する作業が、これからの経営者の新しい仕事になります。

私のクライアントの中には、すでに Claude Code でこの種の閾値設定を始めている方がいます。最初の1か月は試行錯誤ですが、3か月経つと、AIが自分の判断癖を覚えて、閾値の精度が上がってくる。

三木谷さんが「実際の取引まで」と言ったのは、この未来図を想定しています。楽天の出店者がAIエージェントで自動取引を始める時、自分の会社が遅れているかどうかは、**いま、閾値設計の練習を始めているかどうか** で決まるのです。

## 補足：AIアバター三木谷の意味

少し話が脱線しますが、三木谷さんは2025年5月の決算会見で、**AIで生成した「アバター三木谷」** を登場させ、淡々と業績を語らせる演出を見せました（出典：ITmedia AI+）。

これは、ただのエンタメではありません。

楽天グループのトップ自身が、自分の代理として AI に話をさせる、という事実そのものが、「我が社では、トップ層もAIを当たり前に使っている」というメッセージを内外に発信したわけです。

南場会長が「社員として AI を登録している」と語ったのと、同じ構造です。経営トップが、自分の業務の一部を AI に明示的に委譲する。これが、社員と取引先と株主に対する、最強の「AI使用宣言」になっています。

中小企業の経営者が、自社の社員に「AIを使え」と号令をかけるとき、**社長自身が誰よりも先にAIを使っている姿** を見せることが、何より効きます。三木谷さんも、南場さんも、秋好さんも、皆ここを共通してやっています。

## まとめ：明日から始める、4つの行動

ここまでの話を、ひとつにまとめます。

ひとつ。「No AI, No Future」は、煽り文句ではない。AI を触っている経営者と、触っていない経営者の差が、複利のように開いていく時代に入った、という三木谷さんの実感です。3年遅れると、追いつけません。

ふたつ。「使いこなす」とは、AIを賢く操ることではない。AIと自分の対話の中で、自社の業務を再定義していくこと。3つの段階（業務の言語化、判断癖の登録、出力の摺り合わせ）を順に踏みます。

みっつ。トリプル20（マーケ・オペ・クライアント、各20%効率化）は、中小企業のほうが効きます。今週の自分の業務をこの3つに分類し、時間を一番取られている領域から AI に任せます。

よっつ。AIエージェントが「実際の取引まで」やる時代に向けて、**閾値設計** の練習を、今から始めます。「いくら以下なら自動承認」「どの種類のメールは下書きまで」など、自分の会社の判断ラインを、AI に教える作業です。

三木谷さんが楽天市場店舗に向けて発したメッセージは、楽天市場の外側にいる中小企業のオーナーにこそ、刺さるべきものでした。

「AI を使いこなせなくなると、どうしても人の頭脳は衰退していく」

この言葉を、自分の3年後の姿として、想像してみてください。

いつ動き出すか。少なくとも、今でしょう。

## 実装の手引き：自分の会社で「トリプル20」を始める具体手順

ここからは、楽天グループ規模ではなく、**社員 5〜30 人規模の中小企業オーナーが、自分の手で「マーケ・オペ・クライアント」3領域の効率化を始めるための具体手順** を示します。

### 用意するもの（合計：月額 3,000 円＋無料）

- Claude Pro 契約（月額 3,000 円）
- パソコン（Mac か Windows、メモリ 8GB 以上）
- Claude Code（無料、Anthropic 公式サイトからインストール）
- 任意の作業フォルダ（例：デスクトップに `claude-management` フォルダを作る）

### Step 1：CLAUDE.md（経営コンテキスト）を書く（所要 60 分）

作業フォルダに `CLAUDE.md` という名前のテキストファイルを作り、以下の質問に答える形で書き出します。

```markdown
# 私の会社についての取扱説明書（CLAUDE.md）

## 会社の基本情報
- 業種：（例：神奈川県横浜市の和食店）
- 規模：社員 5 名（パート含めて 12 名）
- 主要顧客：地元の常連客 7 割、観光客 3 割
- 売上規模：年商 8,000 万円
- 創業：2018 年

## 今期の3つの目標
1. 売上：年商 1 億円達成
2. 常連リピート率：60% → 70%
3. 新メニュー開発：四半期に1つ

## 私（社長）の判断の癖
- 値段交渉は基本しない（価値で売る方針）
- 採用は人柄重視、スキルは後から教える
- 数字より顧客の声を優先する場面が多い
- 直感的に「合わない」と感じる案件は、たいてい後でトラブルになる

## 文章のトーン
- お客様向け：丁寧、温かみのある言葉、絵文字なし
- 取引先向け：簡潔、結論ファースト
- 社内向け：率直、ねぎらいの一言を必ず添える

## 私が AI に絶対やってほしくないこと
- 顧客に直接 DM を送る（必ず私が承認してから送信）
- 値段の設定（私の判断でしか変えない）
- 退職判断・採用最終判断
```

ここまで書ければ60点。三木谷さんが言う「使いこなす」の第1段階（業務の言語化）に相当します。

### Step 2：トリプル20スキル（マーケ・オペ・クライアント）を作る（所要 60 分）

作業フォルダの中に `.claude/skills/triple20/` フォルダを作り、`SKILL.md` を以下の内容で作成します。

```markdown
---
name: triple20
description: 経営者の業務をマーケ・オペ・クライアント対応の3領域に分類し、各20%の効率化案を出す
---

# トリプル20 効率化スキル

## やること
1. 経営者から「先週やった業務リスト」を入力として受け取る
2. 各業務を以下のいずれかに分類する：
   - マーケティング業務（販促・SNS・資料作成等）
   - オペレーション業務（議事録・定型書類・社内連絡等）
   - クライアント対応業務（顧客メール・問い合わせ・見積もり等）
3. 各カテゴリの業務に対して、AI でどう20%効率化できるかの具体案を提案する
4. 効率化案の優先順位を、削減時間の大きさ順に並べる

## 出力フォーマット

【マーケ業務】
- 業務A（週○時間）→ AIで○時間削減できる方法：◯◯
- 業務B（週○時間）→ ...
（マーケ合計：週△時間 → ▲時間に短縮、削減率○%）

【オペ業務】
... (同様)

【クライアント対応業務】
... (同様)

【総合サマリ】
- 月間で創出できる時間：合計◯時間
- 最初に着手すべきトップ3の業務：...

## 注意事項
- 経営コンテキスト（CLAUDE.md）の判断癖を必ず参照する
- 「AI に絶対やってほしくないこと」リストに該当する業務は、効率化案から除外する
```

これを毎週金曜の終業前に実行すると、自分の業務の分布が見える化されます。

### Step 3：閾値設計シートを作る（所要 30 分）

論点4で出てきた「AIエージェントの閾値設計」を、自分の会社用に書き出します。`thresholds.md` という名前で作成。

```markdown
# AI エージェント閾値設計シート

## 自動承認していい業務
- 3万円以下の定期消耗品の発注
- 既存取引先への定型的な見積もり依頼の返信（過去パターンと一致するもの）
- 予約確認メールの自動送信

## 必ず私の確認を経る業務
- 3万円超の発注すべて
- 新規取引先への見積もり
- 顧客への謝罪メール
- 採用に関する一切の判断
- 退職に関する一切の判断

## 段階的に AI に任せる候補
- SNS 投稿の下書き（最初は人間チェック必須、3か月後に自動投稿許可を検討）
- 月次レポートの初稿作成（3か月運用後、信頼度を見て自動化判断）
```

このシートは、Claude Code に毎回読ませる前提で運用します。

### Step 4：フィードバックループを回す（毎週金曜 15 分）

毎週金曜日の終業前に、Claude Code にこう頼みます。

```
今週の triple20 出力（./outputs/2026-05-10_triple20.md）と
私の実際の業務時間記録（./time_log/2026-05-10〜2026-05-14.md）を読んで、
以下を教えて：
1. 先週の AI 効率化案のうち、実際に試したものの効果は何時間分だったか
2. 試したけど効かなかった案の原因は何か
3. 来週、優先度を上げるべき業務領域はどこか
4. CLAUDE.md か thresholds.md に追記すべき新しい判断パターンはあったか
```

ここで提案された改善点を、CLAUDE.md と SKILL.md と thresholds.md に追記する。これがフィードバックループです。三木谷さんが言う「使いこなす」の第3段階（出力の摺り合わせ）を、毎週仕組み化することになります。

### よくあるつまずきポイント

中小企業のオーナーが Step 1〜4 を進める時、典型的につまずくのは次の 3 点です。

**つまずき 1：そもそもターミナルや Claude Code のインストールができない**
独学では 1〜2 週間かかります。誰かに横で教えてもらえれば 30 分で終わります。

**つまずき 2：CLAUDE.md と thresholds.md が育たない**
最初の60点を書いた後、追記する習慣が続きません。週1回の振り返り時間を、自分のスケジュールに「予約」しておくのが対策です。

**つまずき 3：閾値設計のラインが引けない**
「いくらなら自動承認していいのか」「どの種類のメールは AI に任せていいのか」を、独学で決めるのは難しい。ここは、誰かと一緒に考えるのが圧倒的に早いです。

これらをすべて自力で乗り越えるには、半年〜1年かかるケースが多いです。
