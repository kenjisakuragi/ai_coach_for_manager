# Claude Code経営活用事例｜ランサーズ秋好社長の場合

このシリーズでは、有名経営者の公開発言を題材に、**中小企業のオーナーが Claude Code を経営にどう取り入れるべきか** を読み解きます。

第2回は、ランサーズ株式会社の代表取締役社長 CEO・秋好陽介さんです。

秋好さんは、フリーランス・個人事業主の働き方を支えるランサーズの社長として、2025年5月の通期決算説明会でも「AX で日本産業をアップデートする」と AI 戦略を語りました。

ところが、それだけではありません。

2026年に入って、秋好さんは自身の YouTube で、**自分が Claude Code を使って構築した経営者向けシステムの中身を、まるごと全公開** しました。動画タイトルは「【朝起きたら仕事の8割終わってる】AI が24時間勝手に働く経営者向けの仕組みを作ったので全公開します」です。

ここまで踏み込んで実装の中身を公開した上場企業の社長は、ほとんどいません。

しかも秋好さんは、このシステムを **業務の合間に Claude Code に頼んで作り、1回で完成させた** と述べています。フルでコーディングしていれば半年かかったところを、業務の合間で完成させた。これは、Claude Code の使い方として極めて重要な事例です。

本記事では、秋好さんの動画を 4 つの論点に整理します。最後に、私（桜木）が経営者の方に伝えていることをお話しします。

---

## 論点1：朝6:30〜7:00 の30分で、社長の仕事の8割が終わっている

秋好さんの動画で、いちばん衝撃的なのは、ここです。

> 「6時半起床します。スラックボットから今日のブリーフィングが出てくる」
>
> 「朝起きてから15分の間にこれが起きてる」
>
> 「7時になるって感じ」

朝6:30 に起きた社長が、7:00 までにやっていること。整理するとこうなります。

### 6:30〜6:31（1分）：今日のブリーフィングを確認

スラックに、こういう内容が自動で届いています。

今日のスケジュール。今日の会議一覧。各会議の準備状況。準備不足な会議とその対処法（「秘書のNさんに確認してください」「経営企画のKさんにこの資料の不足をフィードバックします」）。

しかも秋好さんが指示する前に、AI が秘書や経営企画担当に DM を送って、必要な確認を進めています。

> 「準備不足なんで秘書のNさんに確認してください、もしくは経営企画のKさんにここのドキュメントが不足してるっていうフィードバックをしますみたいな……普通に同じスラックでDM行く」

これは、社長が指示するのではなく、**AI が代理で動いている** ということです。秋好さんは朝起きて、その確認をするだけ。

### 6:31〜6:45（15分）：昨日の重要シグナルを確認

「シグナル」というのは、秋好さんが入っていない他の社員の会議の中から、**秋好さんにとって重要な情報を AI が抽出したもの** です。

たとえば、ある社員のミーティングで「AI で M&A 案件を抽出するシステム構想」が議論されていた。これは秋好さんが知っておくべき情報です。普通なら、こういう情報は社長まで上がってきません。ところが AI が拾って、「こういう議論が車内でされていますよ」と知らせてくれます。

> 「うちの会社の約200人いる社員の会議の中で、秋吉さんにとって重要な情報を分析してくれる」
>
> 「1人だけで経営してたのが、20人ぐらいいる感覚から全部の会議になんか同席勝手にしてるみたいな」

社員 200 人の会議をすべて AI が聞いて、社長視点で重要なものだけを 15 件程度に絞って提示する。

### 6:45〜7:00（15分）：戦略アップデートを確認

事業部それぞれに重要 KPI があります。昨日の現場の行動ログ（営業 N さんが Z 社から失注した、など）を、AI が KPI と照合して、影響度を判定します。

> 「Z 社の失中っていう事実が、いやいやZ 社のこのターゲットの中の1番のセンターピンだから、ここ落とすっていうことはここのKPI見立つリスクがあるから、今すぐ秋吉さんこのZ社失中の要因を、Aの事業部長と共に深掘りして戦略アップデートするなり営業のコンセプト説をなんか変えるなりやってください、ていうアラート」

アラートレベルが赤・黄・緑の信号で表示されます。赤が出たら即動く。緑が多い日は、安心して通常業務に進める。

これが、朝7:00 までに終わっています。

秋好さんはこう言います。

> 「これって普通の経営者って毎日やってないし、多分毎日やろうと思ったら10時間とかかかるんじゃない?」

10 時間が、30 分になっている。秋好さん本人の表現では「10 時間が 1 時間になる」です。

## 論点2：「秋吉」というシステムは、何でできているか

秋好さんは、自分のシステムに「秋吉（あきよし）」という名前をつけています。

秋吉の中身は、**5つのスキル** で構成されています。

「スキル」というのは、Claude Code に渡す **専用のマニュアル** のことです。新入社員に「この業務はこういう手順でやってね」と渡す業務マニュアルと、まったく同じ発想です。

5つのスキルを、順に紹介します。

### スキル1：経営コンテキスト

秋好さん自身の頭の中にある、優先順位を AI に教え込んだものです。月1回くらいしか更新しません。

中身は、ランサーズのミッション、3か年計画（28年3月までに営業利益10億円目指す）、今年の主力3事業の方針、今期の重点課題、CEO（秋好さん）の考え方の癖、など。

> 「経営コンテキストってランサーズのミッションとか参加年計画……これIRに出てる話とかじゃ今年FY26年っていうのはこの主力の3事業でこういう風な営業X億円を目指そうと思ってますと」

これがないと、AI は「どの会議が重要か」を判断できません。

### スキル2：会議スキル

会議のランク（A・B・C）、頻度（週1・月1）、参加者、ゴールが、すべて AI に教え込まれています。

これと Google カレンダーの API を組み合わせると、「今日の経営戦略会議は A ランクで、ゴールはこれで、参加者はこれで、過去の議事録はここにあります」という情報が、AI 側に揃います。

### スキル3：会議トラッカー

各会議が終わるたびに「60点」「80点」という点数と理由を記録します。

> 「3週間前、2週間前、1週間前と、どういう風なストーリーでこの軽戦略会議が開かれたかっていうコンテキスト……ストーリーを知ってるから単純に今日だけっていう感じじゃない」

3 週間前、2 週間前、1 週間前と、どういう流れでこの会議に至ったかという文脈を AI が把握します。だから「今日の会議だけ」ではなく、「ここまでのストーリーの中で、今日は何をすべきか」が見える。

### スキル4：重要シグナル抽出

社員 200 人が日々生み出す情報（会議録音、Slack のやり取り、Google ドキュメント）から、社長視点で重要なものだけを抽出します。

種類は、仮説、学び、意思決定、検討中、アイデア、気づき、発見、知識など。

> 「これがね、自分的にはめちゃくちゃ忘れるから。人間だから。自分が喋ってて、それいいねって言ったアイデアとかも忘れちゃうんで。これが出たら次にやってるの」

社長自身が忘れている自分のアイデアまで、AI が拾って提示してくれる。

### スキル5：戦略アップデート

事業部ごとの重要 KPI と、現場の日々の行動ログを照合して、戦略への影響をアラートします。

赤・黄・緑の信号で、社長が何に集中すべきかが、毎朝可視化されます。

### この5つで、何が起こるか

秋好さんはこう述べています。

> 「これがなかったら、俺、そんなシステム開発しようとしてるとか知らない。でも、もしかしたらなくなるかもしれない。でも声かけてミーティングしてっていうことが、なんだろうね。1人だけで経営してたのが、なんか20人ぐらいいる感覚から、全部の会議になんか同席勝手にしてるみたいな」

社長が、200 人の会議全部に同席しているような状態。物理的には不可能なことを、AI が代行しているわけです。

## 論点3：「フィードバックループが80%」が、システムの心臓

秋好さんが、この動画でいちばん強調しているのが、これです。

> 「フィードバックループが1番大事かも。結構ね、このシステム全体の80%はフィードバックループによってアップデートしてた」

80% です。

つまり、最初に作ったスキルやコンテキストは、あくまで **60点のスタート** なんです。残り40点は、毎日使いながら、フィードバックを返して、AI に教え込んでいくことで、80点、90点に育てていく。

具体的には、こういう作業です。

毎回の会議のあとに「60点でした。理由はこれこれ」と AI に教える。AI が「ここの判断は変わりやすい」「ここのシグナル抽出は精度が低い」と気付いたら、コンテキストを修正する。新しい会議のパターンが出てきたら、ルールを追加する。

これは、新入社員の OJT と、まったく同じ発想です。マニュアルを渡しただけでは育たない。毎日「ここはこうしてほしい」「これは違う」と教え続けて、半年で一人前になる。AI も同じです。

ここで、中小企業のオーナーが受け取るべきメッセージは、こうです。

**Claude Code は、買って終わるツールではなく、育てる相棒。**

最初の1か月は60点で、3か月後に80点、半年後に90点になる。これが、秋好さんが言う「フィードバックループ80%」の意味です。

## 論点4：「夢があってギャップを埋める」だけ。エンジニアでなくても作れる

ここまで読んで、こう思った方が多いかもしれません。

「秋好さんはエンジニア出身だから、こういうシステム作れたんでしょ？」

ところが、秋好さん自身がこう否定します。

> 「エンジニア出身だからじゃないかと聞かれるけど、違うと思う」
>
> 「結局、AI だろうがなんだろうが、今があってゴールがあるじゃない。こうなりたいなって朝起きた瞬間にこういう状態になりたいなっていう夢があるから、夢があるからここってギャップじゃない。このギャップを埋めるだけ」

ギャップを埋めるだけ。

つまり、Claude Code でシステムを作るときに必要なのは、エンジニアの技術力ではなく、こうです。

いまの状態を正確に把握できる力。理想の状態を具体的に描ける力。その間のギャップを言葉にできる力。

この3つです。

すべての経営者が、すでに持っているスキルです。日々、社員に対してやっていることと、同じです。「いまこうなってる、こうなってほしい、だから君はここを変えてくれ」。これと同じことを、Claude Code に対してやればいい。

秋好さん自身、このシステムを **フルでコーディングしていれば半年かかった** と推定しています。それが、業務の合間で Claude Code に頼んで、1回で完成しました。

> 「業務してる間に、ちょっと横でクロードコードでやってもらってる空き時間の1回やつでここまで行った」

この一言が、Claude Code の本質を表しています。社長が、自分の業務をしながら、横で Claude Code が動いている。指示は短文。それで、半年かかる仕事が完成する。

## 補足1：マネージャー向け版もある（社員の時間配分を可視化）

秋好さんは、社長版だけでなく、マネージャー向けの社員版も作っていると述べています。

たとえば営業部門でのマネジメント。

> 「Aさんの1日を見たら、新規開拓に使ってる時間 5%ですとか、この人 80%やってますとか出てくる」
>
> 「上司もAさんも共通認識として『あ、今 5%か、じゃあ 80%にしよう』と動ける」

新規開拓と既存顧客対応の時間配分が、社員1人ずつ可視化されます。

これがないと、上司は「Aさんは新規をやってる」と思い込んでいるが、実は5%しかやっていない、ということが起きます。AI が現場の行動ログから時間を抽出してくれるので、ファクトとして見える。

中小企業のオーナーにとっては、社員5〜10人規模でも、これは応用できる発想です。誰が、何にどれくらい時間を使っているか。これがファクトで見えるだけで、マネジメントの精度が上がります。

## 補足2：秋好さんは、筋トレも家事もAIで管理している

動画の冒頭で秋好さんが熱く語るのが、AI のプライベート活用です。

> 「筋トレ中に『デッドリフト 28kg 10 回やります』とつぶやくだけで、AI エージェントが見てモーションに記録される」
>
> 「録音するだけ、iPhone があったらできる」

ジムで筋トレしながら、声で記録する。AI が「何キロを何回やった、何日ぶり」を管理してくれる。

> 「大企業向けのシステムって大企業お金持ってるからシステム開発にお金払えるけど、自分専用の筋トレシステムに開発費 500 万とか払えないでしょ」
>
> 「でも AI があれば本当ね、20分とかでできる」

20分で、自分専用のアプリができる。

これは、中小企業オーナーにとって Claude Code の本質を理解する重要な視点です。**自分の業務に最適化されたシステムを、安く、自分だけのために作れる**。これが、AI 時代の経営者の武器です。

## 中小企業オーナーへの翻訳：「秋吉」の縮小版を、自分も持つ

ここまで読んで、こう思った方も多いかもしれません。

「ランサーズは社員 200 人。うちは社員 5 人だから、こんな大規模なシステムは要らない」

その通りです。秋好さん自身がこう述べています。

> 「社員 10 人だったらこんなシステム要らないし」
>
> 「これは秋吉にしか使えないわけですよ、ぶっちゃけ」

つまり、ランサーズ規模の「秋吉」をそのまま真似する必要はありません。

ところが、**設計思想は完全に同じものを、社員 5 人規模でも持てます**。

たとえば、こういう縮小版です。

朝のブリーフィング小規模版。今日のスケジュール、メールで来た重要な要件、SNS で起きた業界の動き、を毎朝 7 時に整理して Slack に投稿。

重要シグナル小規模版。自分が見落としていそうな顧客からのメール、競合の新サービス、業界ニュースの中から、自分にとって重要なものだけを5件抽出。

戦略アップデート小規模版。自分が立てた今月の目標と、日々の活動ログを照合して、目標達成に向けて軌道修正が必要な点を毎週土曜日に提示。

これだけでも、月に30時間は浮きます。

そして、秋好さんが強調する「フィードバックループ80%」は、規模に関係なく、すべての経営者にとって核心です。最初の60点を、毎日のフィードバックで80点・90点に育てる。

## まとめ：明日から始める、4つの行動

ここまでの話を、ひとつにまとめます。

ひとつ。Claude Code は、朝起きてから7:00までの30分で、社長の仕事の8割を済ませる仕組みを作れる道具です。秋好さんはそれを「秋吉」として実装し、全公開しました。

ふたつ。システムの中身は、5つのスキル（経営コンテキスト・会議・会議トラッカー・シグナル抽出・戦略アップデート）。これを順に教え込めば、社長専用のAIが立ち上がります。

みっつ。完成度の80%は、フィードバックループで決まります。Claude Code は買って終わるツールではなく、毎日のフィードバックで育てる相棒です。

よっつ。エンジニアでなくても作れます。「いまの状態」と「理想の状態」の言語化と、ギャップを言葉にする力。これは経営者がすでに持っているスキルです。

ランサーズの秋好社長が、自分のシステムをここまで全公開した意味は大きいと、私は思っています。**技術ではなく、設計と運用が経営者の仕事**。これを実例で示してくれました。

## 実装の手引き：縮小版「秋吉」を、自分の会社で作る具体手順

ここからは、ランサーズ社員200人版ではなく、**社員5〜30人規模の中小企業オーナーが、自分の手で縮小版「秋吉」を作るための具体手順** を示します。

### 用意するもの（合計：月額3,000円＋無料）

- Claude Pro 契約（月額3,000円）
- パソコン（Mac か Windows、メモリ8GB 以上）
- Claude Code（無料、Anthropic 公式サイトからインストール）
- 任意の作業フォルダ（例：デスクトップに `claude-management` フォルダを作る）

### Step 1：CLAUDE.md（経営コンテキスト）を書く（所要60分）

作業フォルダに `CLAUDE.md` という名前のテキストファイルを作り、以下の質問に答える形で書き出します。

```markdown
# 私の会社についての取扱説明書（CLAUDE.md）

## 会社の基本情報
- 業種：（例：神奈川県横浜市の和食店）
- 規模：社員 5 名（パート含めて 12 名）
- 主要顧客：地元の常連客 7 割、観光客 3 割
- 売上規模：年商 8,000 万円
- 創業：2018 年

## 今期の3つの目標
1. 売上：年商 1 億円達成
2. 常連リピート率：60% → 70%
3. 新メニュー開発：四半期に1つ

## 私（社長）の判断の癖
- 値段交渉は基本しない（価値で売る方針）
- 採用は人柄重視、スキルは後から教える
- 数字より顧客の声を優先する場面が多い
- 直感的に「合わない」と感じる案件は、たいてい後でトラブルになる

## 文章のトーン
- お客様向け：丁寧、温かみのある言葉、絵文字なし
- 取引先向け：簡潔、結論ファースト
- 社内向け：率直、ねぎらいの一言を必ず添える

## よく使う情報源
- 業界ニュース：日経 MJ、フードビジネス
- 競合：駅前の◯◯さん、商店街の××さん
- 過去の議事録：Google Drive の「議事録」フォルダ

## 私が AI に絶対やってほしくないこと
- 顧客に直接 DM を送る（必ず私が承認してから送信）
- 値段の設定（私の判断でしか変えない）
- 退職判断・採用最終判断
```

ここまで書ければ60点。これが「経営コンテキスト・スキル」になります。

### Step 2：朝のブリーフィング・スキルを作る（所要45分）

作業フォルダの中に `.claude/skills/morning-briefing/` というフォルダを作り、`SKILL.md` を以下の内容で作成します。

```markdown
---
name: morning-briefing
description: 朝起きた時に確認したい今日のスケジュール・重要メール・業界ニュースを整理する
---

# 朝のブリーフィング・スキル

## やること
1. Google カレンダーから今日の予定を取得
2. メールから昨日 18:00 以降の未読を確認
3. 業界ニュースサイトから直近24時間の記事を5件取得
4. 上記から「今日、社長が知っておくべき重要事項」を10行以内で要約

## 出力フォーマット

```
おはようございます。今日のブリーフィングです。

【今日の予定】
- 10:00 ◯◯さんとの打合せ（事前準備：◯◯）
- 14:00 ××会議（議題：◯◯）

【要対応メール】
1. △△様：来週の見積もり依頼（期限：今週金曜）
2. ◇◇銀行：口座振替の確認（期限：明日）

【業界ニュース】
- 競合の◯◯が新サービス開始（影響度：中）
- ××の規制改正案（影響度：要注目）

【私からの一言提案】
今日の14時会議は、先週の議事録で「結論未定」とした案件です。
事前に△△さんに状況確認しておくと、会議が短くなります。
```

## 注意事項
- 経営コンテキスト（CLAUDE.md）の判断癖を必ず参照する
```

これで「朝のブリーフィング・スキル」が出来上がります。

Claude Code を立ち上げて「morning-briefing スキルを実行して」と日本語で頼めば、上記の手順に従って動いてくれます。

### Step 3：会議トラッカーを作る（所要30分）

会議が終わるたびに、Claude Code に以下の質問をするだけです。

```
今日の◯◯会議の議事録は ./meetings/2026-05-10_◯◯.md にある。
この会議を100点満点で評価して、点数と理由を ./meetings/tracker.md に追記して。
評価基準は次の通り：
- 議題が明確だったか（30点）
- 結論が出たか（30点）
- 次のアクションが決まったか（20点）
- 時間内に終わったか（20点）
```

これを2週間続けると、`tracker.md` には自分の会議の傾向が記録されます。「いつも結論が出ない」「時間オーバーが多い」といったパターンが見えてきます。

### Step 4：フィードバックループを回す（毎週金曜15分）

毎週金曜日の終業前に、Claude Code にこう頼みます。

```
今週の議事録（./meetings/2026-05-10〜2026-05-14）と
朝のブリーフィング履歴（./briefings/）を読んで、
以下を教えて：
1. ブリーフィングで提示した「私からの一言提案」は、実際の意思決定に役立ったか
2. 今週の会議で、CLAUDE.md に追記すべき新しい判断パターンはあったか
3. 来週、改善すべきブリーフィングのフォーマットはあるか
```

ここで提案された改善点を、CLAUDE.md と SKILL.md に追記する。これがフィードバックループです。

秋好さんが言う「システム全体の80%はフィードバックループ」というのは、このことです。

### よくあるつまずきポイント

中小企業のオーナーが Step 1〜4 を進める時、典型的につまずくのは次の3点です。

**つまずき1：そもそもターミナルや Claude Code のインストールができない**
これは独学では1〜2週間かかります。誰かに横で教えてもらえれば30分で終わります。

**つまずき2：CLAUDE.md が育たない**
最初の60点を書いた後、追記する習慣が続きません。週1回の振り返り時間を、自分のスケジュールに「予約」しておくのが対策です。

**つまずき3：スキルの設計がうまくできない**
「何を入力に、何を出力させるか」の設計が、独学では難しい。ここは、誰かと一緒に考えるのが圧倒的に早いです。

これらをすべて自力で乗り越えるには、半年〜1年かかるケースが多いです。
