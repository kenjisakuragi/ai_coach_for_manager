# ソリューション・カタログ

> 経営者の各業務に対する、Claude Code を中心とした具体的な解決策。
> スモールビジネスの "現実的な" 構成にしています（高度なAPIや独自開発は最小限）。

---

## 全体アーキテクチャ

```
[経営者]
    ↓
[Claude Code（CLI）]  ← 経営者専属のAI（CLAUDE.md で個性記憶）
    ↓
[各種スキル（.mdファイル）]  ← 業務ごとの "型"
    ↓
[ローカルファイル + 外部連携]
    ├── Notion（クライアント・案件DB）
    ├── Google Calendar（予定）
    ├── Gmail/Outlook（メール）
    ├── Slack（チーム連絡）
    ├── 業務ファイル（提案書・議事録等）
    └── Web（ニュース・業界情報）
```

→ スモールビジネスでは **Notion + Claude Code** の組み合わせが最強。
→ 高度な専用ツールは不要、既存のSaaS（freee、Slack等）と連携。

## ソリューション①｜朝のブリーフィング

### 朝6:30起床→朝MTGまでの15分で完了

#### 仕組み
1. 経営者が `claude run morning_brief` を打つ（1コマンド）
2. AIがCLAUDE.md（経営者の好み）を読む
3. 監視対象URLからニュース取得
4. カレンダーから今日の予定取得
5. 過去24時間のメール・Slack要約を取得
6. すべてを "経営者目線" で1ページに整理

#### 出力例
```markdown
## 🌅 〇月〇日（火）モーニングブリーフ

### 今朝の3行サマリ
- 業界AでM&A発表（〇社→〇社）。当社競合への影響中
- 為替が110円台に。輸入コスト+5%相当
- 〇〇法改正の最終案発表。当社は影響少

### 今日の予定（重要度順）
[14:00] X-社 商談 — 過去履歴：3か月前にA案を提示、要追加情報
[10:00] 役員会 — 議題：Q3予算修正
[16:00] 採用面接 — 候補者B、技術面チェック必須

### 私が今日決めること
1. Q3予算の修正幅（営業 vs 開発の配分）
2. X-社への追加提案の方向性

### 緊急で確認すべきメール
- Y-社からの納期変更依頼（24h以内返信推奨）

### 今日の判断に効く1件
為替動向：取引先Z-社との価格交渉タイミングとして好機の可能性
```

#### 構成スキルファイル
- `skills/morning_brief.md`
- `skills/calendar_summary.md`
- `skills/news_relevance.md`

#### 必要な連携
- Notion（経営者の好み・業界キーワード）
- Google Calendar（事前にMCP設定）
- WebFetch（ニュースURL）
- Gmail/Slack（オプション・上級者向け）

#### 経営者の所要時間
朝5分でブリーフを読む → 1日の判断モード起動完了

## ソリューション②｜議事録の完全自動化

### 会議終了→Slackで全員に共有まで2分

#### 仕組み
1. 会議をZoomで録画
2. tldv（または Otter / CLOVA Note）で自動文字起こし
3. 経営者が `claude run meeting_summary` を実行
4. AIがCLAUDE.mdに従って要約
5. 自動でSlack/メールに送信（オプション）

#### 出力フォーマット（経営者用）
```markdown
## 📋 〇月〇日 役員会

### 決定事項
- Q3予算修正：営業+20%、開発-10%
- 新規プロダクトA、9月ローンチ確定

### 次のアクション
| 担当 | アクション | 期限 |
| 田中 | 営業計画修正 | 6/15 |
| 佐藤 | 採用計画調整 | 6/20 |

### 論点として残ったもの
- 役員人事のタイミング（次回再議）

### あなた（社長）が次に判断すべきこと
- 新規プロダクトAの責任者指名
- 役員人事のスケジュール

### 気になる発言
- 田中CFOの "下期は守り" 発言 → 来期の方針議論で深掘り推奨
```

#### スキルファイル
- `skills/meeting_summary_board.md`（役員会用）
- `skills/meeting_summary_1on1.md`（1on1用）
- `skills/meeting_summary_client.md`（顧客MTG用）

#### スモールビジネス向けの工夫
- Zoom Pro契約（月¥2,500）で自動録画
- tldv 無料プラン（月10時間まで）で文字起こし
- → **追加費用ゼロ〜月¥2,500で完結**

## ソリューション③｜クライアント情報の構造化

### "あれ、誰だっけ" を10分→3秒に

#### Notion DB の設計
```
クライアントDB
├── 仮名（X-社、Y-社）
├── 業種・規模
├── 取引開始日
├── キーパーソン（仮名 + 役職 + 関係性）
├── 直近の重要やり取り（最大3件）
├── 次のマイルストーン
├── 警戒すべきパターン
└── ファイル（議事録・提案書のリンク）
```

#### Claude からの参照
```
$ claude
> X-社について教えて

→ Notion APIから取得 → 要約して返答

> X-社の田中部長との次回ミーティング、何を準備すべき？

→ 過去の議事録 + 約束 + 次のマイルストーンを参照 → 提案
```

#### スキルファイル
- `skills/clients_lookup.md`：基本情報参照
- `skills/clients_prep.md`：MTG前の準備
- `skills/clients_history.md`：過去履歴の検索

#### 移行支援（パッケージ提供価値）
3か月の中で、経営者の脳内にある **5〜10社分のクライアント情報** を Notion に構造化。
これだけで月10時間の検索時間が消える。

## ソリューション④｜営業・問い合わせ対応の半自動化

### 提案書1から書く→過去案件をベースに5分で

#### 仕組み
1. 過去の提案書5-10本をNotionに格納
2. CLAUDE.md に "提案書の型"（章立て・トーン）を記録
3. 経営者が問い合わせ内容を貼って `claude run proposal_drafter`
4. AIが類似案件を参照して下書き生成
5. 経営者が30秒で確認・微調整 → 送付

#### 営業フロー全体
```
[問い合わせ受信]
  ↓ 自動で `inquiry_response.md` で1次返信ドラフト
[経営者が承認]
  ↓ 商談設定
[商談実施]
  ↓ 議事録自動化
[商談後] `followup_email.md` でフォロー下書き
  ↓
[提案書必要] `proposal_drafter.md` で下書き
  ↓
[失注]　`loss_analysis.md` でパターン蓄積
```

#### スキルファイル
- `skills/inquiry_response.md`
- `skills/proposal_drafter.md`
- `skills/quote_drafter.md`
- `skills/followup_email.md`
- `skills/loss_analysis.md`

#### 削減時間
営業1件あたり1〜2時間 → 15-30分。月10件なら月10〜15時間。

## ソリューション⑧｜意思決定の壁打ち

### 経営判断の質UP・孤独感の解消

#### 3つの壁打ちパターン

##### 論点整理型
```
> claude
> 私はいま、〇〇〇〇という決断をしようとしています。
> 状況は[状況説明]。
> 論点を3つに絞って、それぞれの選択肢を整理して。
> 私が見落としている観点があれば指摘して。
```

##### 賛成・反対両論型
```
> 私は〇案を選ぼうとしています。
> 強く反対する人がいるとして、最も論理的な反対意見を3つ。
> それに対する私の再反論案も。
```

##### 影響先洗い出し型
```
> この決定が顧客・社員・取引先・株主・自分にどう影響するか、
> ポジティブ／ネガティブ／要対応 で整理して。
```

#### スキルファイル
- `skills/decision_logic.md`：3パターン統合
- `skills/decision_log.md`：判断の蓄積
- `skills/risk_scenario.md`：リスクシナリオ生成

#### スモールビジネス向け工夫
- 配偶者・パートナーへの説明文も同時生成（個人事業主の場合）
- 1か月単位の振り返り（"先月の判断、結果どうだった？"）

## ソリューション⑩｜ナレッジベース構築

### "頭の中" を全部記録

#### 構造
```
~/AI_Chief_of_Staff/
├── CLAUDE.md（経営者の取扱説明書）
├── skills/（10-20本のスキルファイル）
├── clients/（クライアント情報）
├── projects/（進行中プロジェクト）
├── decisions/（過去の意思決定ログ）
├── people/（社員・パートナー情報）
└── knowledge/（業界知識・ノウハウ）
```

#### 価値
- 経営者が休んでも、後継者がここを読めば事業が回せる
- 引き継ぎ可能な状態 = 売却可能な事業
- "頭の中" が組織の資産になる
