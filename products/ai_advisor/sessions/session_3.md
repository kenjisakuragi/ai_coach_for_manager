# 第3回｜意思決定支援とナレッジ化（90分）

## このセッションの位置づけ

**"AIが時間を取り戻す道具" から "AIが経営判断の質を上げる相棒" へ昇格させる回**。
ここで以下の体感が得られると、AI顧問の継続意思が劇的に高まる：
- 孤独な経営判断にAIが並走してくれる安心感
- "見落としていた論点" を引き出される驚き
- 属人化していた情報が組織の資産になる手応え

**講師の最大の任務**：
- "ただの効率化" を超えた価値を体験させる
- 顧客本人の実際の経営判断で壁打ちを実演する
- 第4回・継続・法人化の伏線を自然に張る

---

## 事前準備

### 講師側
- [ ] 顧客の時間計測シート（2週間分）を読み込む
- [ ] 顧客が事前共有した "迷っている経営判断" を読んで、3パターンの壁打ち想定を準備
- [ ] 顧客の業界の最近の動向を把握（壁打ち時の文脈として）
- [ ] 属人化解除のための仮テンプレ（顧客向けの "クライアント情報" 構造）を準備

### 顧客側（事前案内）
- [ ] 第2回からの2週間の時間計測結果を確認可能な状態に
- [ ] "最近迷っている経営判断" を1件、Slackに事前共有（3行程度）
- [ ] 属人化していると感じる業務を1つ思い浮かべておく（クライアント管理／案件管理／人脈管理など）

## 詳細スクリプト（時間刻み）

#### 講師の発言

#### 一緒に集計

#### 次の発言（重要）

> **判断の質を上げる役割** をしてもらいます。
>
> 経営者の最大の仕事は、決めること。
> その瞬間にAIが隣にいる、というのが今日のテーマです。」

### 10〜25分｜意思決定の質を上げる "3つの型"（15分）

#### 1スライドで提示

| 型 | 何をする | いつ使う |
|---|---|---|
| **論点整理型** | 散らかった情報から論点を3つに絞る | 情報過多で迷っている時 |
| **賛成・反対両論型** | 自分の決断に対する反対意見をAIに出させる | 自信のある決断ほど使うべき |
| **影響先洗い出し型** | この決定で誰に何の影響が出るかを網羅 | 重要な決定の直前 |

#### 各型のプロンプトテンプレ

##### 論点整理型
```
以下のテーマで決断する必要があります。
現時点の状況：[状況を3〜5行]

論点を3つに絞り、それぞれに対する選択肢を整理してください。
私が見落としている観点があれば指摘してください。
```

##### 賛成・反対両論型
```
私は今、以下の決断をしようとしています。
[決断の内容]

この決断に対して、強く反対する人がいるとします。
最も論理的で説得力のある反対意見を3つ書いてください。
それに対する私の再反論案も提示してください。
```

##### 影響先洗い出し型
```
私は以下の決定をします。
[決定の内容]

この決定で、以下のステークホルダーごとに影響を整理してください：
- 顧客
- 社員
- 取引先
- 株主・投資家
- 自分自身

それぞれに、ポジティブ／ネガティブ／要対応の3区分で。
```

#### 講師の発言
> 「これら3つは、皆さんが普段、頭の中で **無意識にやっていること** です。
> でもひとりだと抜け漏れる。Claude を使うと、3分で網羅的に出せます。」

### 25〜45分｜壁打ちパターン｜実演（20分）

#### 顧客の実題で実演

事前共有された "迷っている経営判断" を画面で開く。

##### 例：「新規プロダクトの責任者を社内で誰にするか決めかねている」

#### Step 1: 論点整理型をライブ実行

```bash
claude
> 私はいま、新規プロダクトの責任者を決めようとしています。
> 候補は3人います: A（営業部長, 35歳, 社外の人脈強い）、
> B（開発リーダー, 40歳, 技術力高いがマネジメント未経験）、
> C（外部からのスカウト, 45歳, 同業界経験豊富だが社内文化に馴染むかは未知）
>
> 論点を3つに絞り、選択肢を整理して。私が見落としている観点があれば指摘して。
```

#### 顧客と一緒に出力を読む
- 出てきた論点で「あ、確かにそれ考えてなかった」となる瞬間を狙う
- 出てきた選択肢に対する顧客の反応を聞く

#### Step 2: 賛成・反対両論型を続けて実行

顧客が傾いている案を仮決定として：
```
私は B（開発リーダー）を選ぼうとしています。
これに強く反対する人の論理的な反対意見を3つ。
```

→ 「マネジメント未経験で部下が辞めるリスク」「開発が手薄になる」など出る

#### 顧客の反応を引き出す
- 「これ、考えてました？」
- 「もし B を選ぶなら、これらの反対意見にどう備えますか？」

#### Step 3: 顧客本人が次のテーマで自分でやってみる

「もう1つ、迷っている件、何かありますか？」
→ 顧客が出してきたテーマで、講師は隣で見守るだけ。
→ 顧客自身がプロンプトを書いて、Claudeと壁打ちする時間を作る（3〜5分）

#### 講師の発言（成功体験）
> 「いま起きたこと、お分かりですか？
> 5分前、皆さんの中にあった "なんとなくのモヤモヤ" が、いま、論点と選択肢として **言語化** されました。
>
> Claudeは答えを出さない。**あなたの判断のための材料を整える** 役割です。
> 最終決定は皆さん。でも判断の質は確実に上がります。」

### 45〜70分｜属人化解除｜クライアント情報の構造化（25分）

#### 講師の問題提起
> 「もうひとつ、経営者あるあるの問題があります。
> 重要な情報を、自分の頭と手元のメモにだけ持っている。
>
> "あの担当、誰だっけ" "3か月前にこの件で何を約束したっけ" を、
> 毎回検索する。これが月5〜8時間です。
>
> 今日はここを片付けます。」

#### Step 1: 棚卸し対象を選ぶ

顧客と一緒に：
- クライアント情報（最有力候補）
- 案件・プロジェクト情報
- 人脈・キーマン情報
- 投資先・ポートフォリオ情報

→ どれか1つを選ぶ（クライアントが圧倒的に多い）

#### Step 2: ファイル構造を一緒に設計

```
~/AI_Chief_of_Staff/
├── CLAUDE.md
├── skills/
└── clients/
    ├── _template.md（共通フォーマット）
    ├── A-社/
    │   ├── overview.md（基本情報・キーパーソン）
    │   ├── history.md（やり取り履歴）
    │   └── next_actions.md（次の動き）
    ├── B-社/
    └── C-社/
```

#### Step 3: テンプレートを一緒に作る

```markdown
# A-社｜概要

## 基本情報
- 会社名（仮）：A-社
- 業種：
- 規模：
- 取引開始：
- 契約形態：

## キーパーソン
| 氏名 | 役職 | 関係性 | 特徴・好み |
|---|---|---|---|
|  |  |  |  |

## ステータス
- 現在の関係（深耕中／拡大期／継続安定／要注意）
- 次のマイルストーン
- 重要な制約・配慮事項

## 過去の重要な約束・コミット
- [日付] 何を約束したか
- [日付] ...

## 私の所感
- このクライアントとの付き合いで大事にしていること
- 警戒すべきパターン
```

#### Step 4: 1社分を一緒に入れる

顧客の頭の中にある A-社（仮称）の情報を、講師が質問しながら引き出して入力。
※ 講師は "聞き出し屋" に徹する。

15分で1社分が完成。

#### Step 5: Claude との連携を確認

```bash
claude
> A-社について教えて
```

→ 入力したoverview.mdを読んだClaudeが要約して返す

```bash
> 来週A-社と打ち合わせがある。準備すべきポイントを整理して
```

→ 過去の約束・現在のステータス・次のマイルストーンから論点抽出

#### 講師の発言
> 「いま起きたのは、**皆さんの頭の中の暗黙知が、組織の資産になった瞬間** です。
>
> 続きの2社、3社、10社... これを月末までにやれば、
> 来月から検索10分が消えます。月5〜8時間。
>
> そして何より、**もし皆さんが3日休んでも、後継者が引き継げる** 状態になります。」

## トラブルシューティング・FAQ

### Q. 壁打ちで "そうなんだ" 程度の浅い気付きしかない
A. 顧客の質問が浅い可能性。講師が質問の "深掘り例" を見せる：
- 「3年後、この決定を振り返って後悔するとしたら何が原因？」
- 「この決定に最も傷つく人は誰？」
- 「この決定が間違っていたと、いつ気付ける？」

### Q. クライアント情報を入れるのが時間かかりすぎる
A. 完璧主義を捨てる。最初は **20% の情報量で OK**。
- 名前と業種と1行コメントだけでも、無いよりマシ
- 過去メールを Claude に "要約して" と渡せば10分で整理できる
- 残り80%は使いながら追記

### Q. 機密情報を含むので、AIに渡すのが怖い
A. CLAUDE.md に「クライアント名は X-社、Y-社 と仮名化する」と明記。
スキル側で実名→仮名の変換を組み込む。
読み込み時はディスクから直接、Claude API に送る前にローカルでマスキングする運用。

### Q. 朝の判断材料スキルが動かない
A. カレンダー連携が必要。MCPで Google Calendar / Outlook を接続するのが本格運用。
それまでは、カレンダーから今日の予定をコピペして入力する簡易版でOK。
