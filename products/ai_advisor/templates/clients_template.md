→ Claude が overview.md / history.md / next_actions.md を読んで、論点を整理

### 例3｜過去の約束の確認

## 仮名化のルール（重要）

機密性確保のため：
- 会社名は X-社、Y-社、Z-社 のように仮名化
- 個人名はイニシャル（T氏、S氏）または役職のみ（CEO、CFO）
- 数字は概算で（売上1.2億 → 約1億）
- 業界・規模は記載OK

→ Claude API に送られても個人を特定できない設計

→ ローカルファイルでは実名を使い、Claude送信時に変換するスキルもあり（応用編）

## 蓄積のコツ

### 完璧主義を捨てる
- 最初は **20% の情報量で OK**
- 「使いながら追記」で十分
- 名前と業種と1行コメントだけでも、無いよりマシ

### 入れすぎない
- 履歴は重要な意思決定や印象的な発言だけ
- 詳細な議事録は別途（議事録要約スキルで生成）

### 月1回のメンテナンス
- _index.md を最新化
- 期限が過ぎたアクションを整理
- 関係性が変わったクライアントのステータス更新

## 1社目の入れ方（第3回セッション内で実施）

### Step 1: 重要顧客を1社選ぶ
- 取引額の大きさ
- 関係性の複雑さ
- 私の頭の中だけにある情報量

### Step 2: 講師の質問に答える形で入力
講師が以下を質問：
- 会社名と業種
- キーパーソン（最大3人）
- 直近の重要なやり取り
- 次のマイルストーン
- 警戒すべきパターン

→ 15分で1社分が完成する

### Step 3: Claude に投げてみる
```bash
claude
> X-社について教えて
```

→ 入力内容を要約して返してくる ＝ うまく動いている証拠

5〜10社分が揃うと：

### 検索10分が消える
- 「あの担当、誰だっけ」を Claude に聞けば3秒
- 過去の約束も自動抽出

### MTG準備が10分→1分
- 来週のX-社MTGの準備を1コマンドで生成

### 引き継ぎ可能な状態
- 自分が3日休んでも、後継者が読めば理解できる

### 法人化への布石
- "属人化解除の威力" を社内で証明できる
- 法人パックの説得材料になる
