# AI顧問サービス｜第1月ブーストカリキュラム

## 設計思想

### 全体ゴール（4回終了時の到達点）
- 経営者本人のPCにClaude Codeが動いている（環境構築完了）
- 自分の業務に最適化された **CLAUDE.md v1** が完成している
- 月30時間を取り戻す **自動化スキルが最低5本** 動いている
- "釣り方"を体得し、第2月以降は自分でスキルを増やせる状態になっている
- **可視化された成果**（時間短縮の実測、生成物のサンプル）を持っている

### 設計原則
1. **すべての回で"動くもの"を作る**：抽象論や座学はゼロ。経営者は成果物にしか反応しない
2. **経営者本人の業務素材を使う**：汎用例ではなく、その人の議事録／メール／資料で実演
3. **既存スキル（部下への指示）の延長として教える**：プログラミング用語を使わない
4. **次の1週間の宿題を毎回設定**：定着のため
5. **すべて録画＋AI議事録で振り返り可能**：経営者は忙しい、復習の心理障壁を下げる

### 各回の構成テンプレート（60〜90分）
| 時間 | パート | 内容 |
|---|---|---|
| 0〜5分 | チェックイン | 前回宿題の成果確認、今日のゴール宣言 |
| 5〜15分 | 概念のコア | 今回のテーマを"経営者の言葉"で1スライドで説明 |
| 15〜45分 | ライブ実装 | 経営者本人の業務素材で一緒に手を動かす |
| 45〜70分 | カスタマイズ | その人特有の業務に合わせて調整 |
| 70〜85分 | Q&A・次の壁打ち | 次回までの宿題確定、関連質問 |
| 85〜90分 | 締め | 議事録自動生成の確認、Slackチャンネル誘導 |

### 事前準備（入会時に依頼）
入会から第1回ミーティングまでの間に経営者に依頼する事前ワーク：
- [ ] 普段使うPC（Mac推奨、Windowsも可）の準備
- [ ] Claude（Anthropic）アカウント作成・Pro契約
- [ ] 直近1週間の業務時間ログ（ざっくりでOK・スプレッドシートで提供）
- [ ] 取り戻したい業務トップ5（ヒアリングシートで提供）
- [ ] 自社の議事録／メール／資料のサンプル3点（NDA締結後にSlack共有）

## 第1回｜環境構築＋業務棚卸し

### この回のゴール

### この回の"刺さる一言"
> 「いま画面に映っているのが、これからあなたに24時間並走するAIチーフ・オブ・スタッフです。今日は、彼に"あなたという経営者"を覚えてもらう日です」

### 詳細アジェンダ（90分）

#### Part 1｜チェックイン（0〜5分）
- 自己紹介（経営者本人と講師）
- 「今日終わったとき、画面の中に何があれば成功か」を経営者に宣言してもらう

#### Part 2｜AIチーフ・オブ・スタッフという発想（5〜15分）
- "Claude Codeはツールではなく、新人秘書を採用するのに近い"
- 新人秘書を育てる3つの要素：
  1. **取扱説明書**（CLAUDE.md）＝あなたの会社・性格・好み
  2. **指示の出し方**（プロンプト）＝部下マネジメントと同じ
  3. **得意技集**（スキル）＝定型業務の自動化レシピ
- 今月4回でこの3つを完成させる、と全体像を提示

#### Part 3｜環境構築ライブ（15〜45分）
画面共有しながら経営者本人のPCで実施。
- Claude Code CLIインストール（事前にインストール手順書をSlackで送付）
- 認証
- 作業ディレクトリの作成（例：`~/AI_Chief_of_Staff/`）
- 動作確認：`claude` で起動、簡単な対話
- **第1の成功体験**：「私の名前を覚えて、次から〇〇さんと呼んでください」を実演

> ⚠️ つまずきポイントの想定
> - ターミナル起動への抵抗 → 「これはWordやExcelより簡単な"指示書アプリ"です」
> - Node.js / brew 等の前提インストール → 事前送付の手順書で対処
> - 認証エラー → スタッフが事前にチェック

#### Part 4｜業務棚卸し（45〜70分）
- 事前提出された「業務時間ログ」と「取り戻したい業務TOP5」を画面共有
- 講師が一緒に分類：
  - **A: 自分にしかできない**（戦略決定、対人重要面談）→ 触らない
  - **B: 自分じゃなくてもいい**（議事録、情報収集、下書き）→ 自動化候補
  - **C: そもそもやらなくていい**（惰性業務）→ 廃止候補
- B群の中から **第2回で実装する自動化スキル候補3本** を経営者と合意

#### Part 5｜CLAUDE.md v1 を書き始める（70〜85分）
- テンプレートを画面共有しながら一緒に埋める
- セクション構成：
  ```
  # 〇〇さんのClaude取扱説明書

  ## 私について
  - 名前／会社／役職
  - 経営している事業の一行説明

  ## 私の好み
  - 文章のトーン（です・ます／だ・である）
  - 長さの好み（簡潔／詳細）
  - 絵文字の有無

  ## 私が大事にしていること
  - （3〜5項目）

  ## 触れてはいけないこと
  - 機密情報の扱い
  - 触れない話題
  ```
- 完成した CLAUDE.md を作業ディレクトリに保存
- **第2の成功体験**：CLAUDE.mdを置いた状態でClaudeに「自己紹介して」と聞き、自分仕様の応答が返ることを確認

#### Part 6｜次回までの宿題（85〜90分）
- [ ] CLAUDE.md v1 を1週間使い倒す（毎日3回以上Claudeに何か聞く）
- [ ] 違和感のあった箇所をメモする（次回でアップデート）
- [ ] 第2回で自動化する業務素材（議事録1本／情報収集対象URL／下書きしたいメール例）をSlackに置く

## 第2回｜"30時間を取り戻す"自動化設計

### この回のゴール
- **3本のカスタムスキル**が動いている：
  1. 議事録要約スキル（録音／文字起こし→要点・決定事項・宿題抽出）
  2. 情報収集スキル（指定URL／キーワードから朝の判断材料を生成）
  3. 下書きスキル（メール／LinkedIn／Slack投稿の最初の80%を生成）
- 1週間使った時の **時間短縮の実測値** を取る運用フローが整っている

### この回の"刺さる一言"
> 「今日の終わりには、月20時間分の業務が、ボタン1つで終わるようになっています」

### 詳細アジェンダ（90分）

#### Part 1｜チェックイン（0〜5分）
- 第1回からの1週間で「Claudeに何を聞いたか」をシェア
- 違和感のあったポイントを聞き、CLAUDE.mdを微修正

#### Part 2｜"スキル"という考え方（5〜15分）
- スキル＝「いつもこの手順でやって」という指示書
- 部下マニュアルと同じ：1度作れば毎回同じ品質
- 今日作る3本は **"自分のためのSaaS"** を3個作る感覚

#### Part 3｜スキル①：議事録要約（15〜40分）
経営者本人の議事録サンプルを使ってライブ作成。
- スキルファイル `skills/meeting_summary.md` を作成
- 構造：
  ```
  # 議事録要約スキル
  
  ## 入力
  会議の文字起こしテキスト
  
  ## 出力フォーマット
  ### 決定事項（経営判断のみ）
  ### 次のアクション（誰が・いつまでに）
  ### 論点として残っているもの
  ### 〇〇さん（経営者本人）が次に判断すべきこと
  
  ## トーン
  簡潔。ですます調。最大A4半分。
  ```
- 経営者の実際の議事録で実行 → アウトプットを見て微調整
- **成功体験**：いつも30分かけていた議事録整理が90秒で終わる瞬間

#### Part 4｜スキル②：朝の情報収集（40〜60分）
- 経営者が普段チェックしているURL／業界キーワードをヒアリング
- スキルファイル `skills/morning_brief.md` を作成
- WebFetchまたはMCP経由で対象URLから情報取得→要約
- 出力フォーマット：
  ```
  ## 今朝の3行サマリ
  ## 業界ニュース（重要度順 トップ3）
  ## あなたの会社／競合への影響
  ## 〇〇さんの今日の判断に効きそうな1件
  ```
- 経営者本人の関心領域に合わせてカスタマイズ
- **成功体験**：朝15分の情報収集が1分に短縮される

#### Part 5｜スキル③：下書きジェネレータ（60〜75分）
- 経営者が頻繁に書く文書タイプを1〜2個ヒアリング（取引先メール／LinkedIn投稿など）
- スキルファイル `skills/drafter.md` を作成
- 過去の本人の文章サンプル3〜5本をスキル内に取り込み、トーンを学習させる
- ライブで「来週の取引先MTGの依頼メールを下書きして」を実行
- 微調整して納得のいくトーンに仕上げる

#### Part 6｜時間計測の運用設計（75〜85分）
- 1週間、3スキルを使った時の時間短縮を計測する簡易シート（Notionテンプレ）を共有
- 「Before / After（分）／削減時間／満足度（5段階）」の4項目のみ
- スキル使用時に1分で記録できる形に

#### Part 7｜次回までの宿題（85〜90分）
- [ ] 3スキルを毎日使い、時間計測を記録する
- [ ] 第3回で扱う"意思決定の壁打ち"用の素材（最近迷っている経営判断1件）をSlackで共有
- [ ] CLAUDE.mdに今週気付いた追加項目を加える

### 第2回の成果物

## 第3回｜意思決定支援とナレッジ化

### この回のゴール

- **意思決定の壁打ちパターン** が確立している（孤独な経営判断にClaudeを使える）
- **属人化解除の第一歩**（クライアント情報・社内ナレッジの構造化）が始まっている

### この回の"刺さる一言"
> 「経営者の最大の仕事は決めること。今日からClaudeは、あなたの隣で材料を揃え、論点を整理し、決断の質を一段上げる存在になります」

### 詳細アジェンダ（90分）

#### Part 1｜チェックイン（0〜5分）
- 第2回からの1週間の時間計測結果をレビュー
- 「もっとも効いたスキル」「うまくいかなかったスキル」を聞く
- 削減時間の実測値を可視化（「すでに月〇時間取り戻している」）

#### Part 2｜意思決定の質を上げる3つの型（5〜20分）
1. **論点整理型**：散らかった情報から論点を3つに絞る
2. **賛成・反対両論型**：自分の決断に対する反対意見をAIに出させる
3. **影響先洗い出し型**：この決定で誰に何の影響が出るかを網羅する

#### Part 3｜朝の判断材料生成スキル（20〜45分）
第2回の `morning_brief` を発展させて意思決定支援版を作る。
- スキルファイル `skills/morning_decisions.md`
- 構造：
  ```
  ## 今日あなたが決めるべきこと（カレンダーから抽出）
  ## それぞれの意思決定に必要な情報（過去のSlack/メール/資料から自動収集）
  ## 想定される論点と選択肢
  ## 私（Claude）の所感（最終判断はあなた）
  ```
- カレンダー連携／メール連携が可能ならMCPで接続（できなければ手動貼付け版）
- 経営者本人の翌日の予定で実行 → 翌朝の朝の使い勝手を確認

#### Part 4｜壁打ちパターンのライブ実演（45〜65分）
事前提出された「最近迷っている経営判断1件」をその場で扱う。
- 講師が経営者の隣で、Claudeに対する3つの問いかけを実演：
  - 「この判断、私が見落としている論点はないか？」
  - 「この決定に強く反対する人がいるとしたら、どんな論理で反対する？」
  - 「半年後に振り返って後悔するとしたら、どんな理由か？」
- 経営者本人が次の壁打ちを自分でやってみる
- **成功体験**：自分の中にあったモヤモヤが言語化される瞬間

#### Part 5｜属人化解除の第一歩：クライアント／案件メモの構造化（65〜80分）
- 経営者が記憶頼りで管理しているもの（クライアント、案件、人脈）を1つ選ぶ
- ファイル構造を一緒に設計：
  ```
  clients/
    └── 〇〇社/
          ├── overview.md（基本情報・キーパーソン）
          ├── history.md（やり取り履歴）
          └── next_actions.md（次の動き）
  ```
- 既存メールやSlackから情報を抽出してClaudeに整理させる
- "あなたが倒れても引き継げる状態"の入り口を作る

#### Part 6｜次回までの宿題（80〜90分）
- [ ] 朝の判断材料スキルを毎朝起動して使う
- [ ] 1日1回、何かの判断を壁打ちパターンで言語化する
- [ ] クライアント／案件メモを最低3件作る
- [ ] 第4回で自動化したい「発信／対外コミュニケーション」を1つ決めてSlack共有

### 4. 録画・議事録の自動化
- 全回録画必須（Zoom／Google Meet）
- AI議事録ツール（tldv等）で自動文字起こし
- 議事録テンプレ：今日の決定事項／次回までの宿題／作成したファイル一覧
- 経営者には終了後30分以内に議事録URLをSlackで送付

### 5. つまずき検知と即時対応
- 各回終了から24時間後に「Claudeを開きましたか？」チェックインメッセージ自動送信
- 開いていない場合：5分の電話 or Slack DMでハードルを取り除く
- 開いている場合：使い込みを促すヒント送付
